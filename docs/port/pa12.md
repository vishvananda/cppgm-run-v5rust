## Previous callable copy/move group and architecture review

Recursive copy properties remain separate from callable plans. A property owns
a pending/in-progress/ready `ConstructorId` memo. An explicit dependency stack
walks only the recorded selected subobject edges, completing each child before
its parent; it does not run overload resolution again or synthesize syntax.

A demanded constructor borrows its canonical class, source signature and
selection facts. Its unit-owned plan holds declaration-ordered
`CopyTarget::{Base(index),Member(EntityId)}` actions with `TypeId` and optional
selected child `ConstructorId`. Implicit callable entries get a public inline
function identity and one positional source parameter; an origin enum selects
`other` in the LowIR prologue. Written defaulted entries retain their original
parameters, declaration identity, exception source and complete/base variants.
A written out-of-class definition publishes its callable plan. Repeated uses
share the memo; unused implicit bodies are not emitted.

Lowering preserves constructor calls versus trivial storage transfers. It
handles recursive base/member copies, move-selected child calls, references
rebound as pointers, scalar arrays and flattened class arrays. The leading run
of trivial subobjects uses one storage prefix. Complete-object and base-entry
limits protect reused tail padding; empty objects/subobjects preserve the C++
evaluation/address rules. Direct local initialization still calls a written
trivial move constructor; delegation to a selected trivial copy instead uses
storage or prvalue materialization. Both copy/move constructor pointer operands
retain noalias/object extents through the existing entry interface.

Constructor and assignment bit-field transfers share one typed storage-view
algorithm. It transfers a safe adjacent allocation unit once, respects
zero-width separators, volatile/overlapping subobjects and the appropriate byte
limit, and retains field-wise operations where a unit transfer is unsafe.
Assignment selection and body ordering are otherwise unchanged.

Class arrays unroll through eight elements and use one target-width prefix
counter above eight. Completed destructible subobjects join an address-owned
plain cleanup chain only where a later copy/default evaluation can throw.
Handlers destroy the completed prefix in reverse order, including flattened
arrays, and guard a throwing destructor with terminate handling. A successful
array replaces its element records with one array action when needed by a later
copy. No array walk uses native recursion.

Default-argument temporaries end with their selected copy call. Ordinary
segments serve the first copy; nested explicit temporary regions serve a call
inside a completed-object chain. Throwing temporary destructors close the
ordinary segment before normal destruction. Scope state is restored after the
call. Caller-owned by-value default arguments use their recorded class passing
facts. The boundary worklist follows demanded constructor identities and
selected nontrivial copy actions, preparing those signature facts exactly once
instead of examining unrelated functions.

The ownership regression verifies unchanged syntax node counts, one reused
constructor memo, public implicit access, an unprepared unused class, an
undemanded move plan and an external leaf body that remains external. All body,
array, temporary and cleanup state belongs to one `Function`; the program keeps
only typed LowIR and entry aliases. No optimizer, allocator or native owner is
changed. No unsafe code, new dependency, environment/process access, reference
recognition, textual phase transport or compiler fallback is introduced.

### Findings and corrections

1. **Nested conditional local construction opened an extra tracked region.**
   Rust retained only a call's insertion position, losing the C++ `CallMark`'s
   declaration origin. `V w = a ? (b ? v : V(2)) : V(3)` and its direct-init
   counterpart emitted an extra `eh_try`/`eh_end` before branching. Call marks
   now retain a typed declaration flag. A named destination identifies its
   outer construction call; tracked earliest-call placement excludes that
   mark, while ordinary call-region placement still sees it. Both forms and
   nested arguments/repeated declarations now match exact C++ bytes.
2. **Ordinary branch copy default temporaries returned status 86.**
   `V w = c ? v : V()` with `V(const V&, const T& = T())` lacked the ordinary
   conditional guard scope supported by C++. Class-conditional materialization
   now owns the outermost flag-reset insertion position; nested branches retain
   its advancing position. A branch temporary sets its flag before closing its
   construction region, survives the outer transfer, and is destroyed only on
   the path where it was made. It does not force whole-expression tracking.
   Normal cleanup preserves the C++ flag-test region and continuation order.
3. **Throwing copy-default temporary destructors had incorrect unwind ownership.**
   Their construction region could cover normal destruction and destroy the
   same temporary again on failure. Temporary destruction now closes that
   region first and uses explicit earlier-object suffixes. A throwing temporary
   destructor after local initialization also owns a cleanup for the completed
   local, above the earlier temporary suffix. These are typed chain records;
   building the handler does not clone or temporarily truncate the cleanup
   vector. Inert local destructors remain governed by the existing C++ rule.
4. **Class-valued copy default arguments lacked demanded destructor identities.**
   A selected `C(const C&, B = B())`, where `B` has destructible members, could
   fail at `implicit recursive destructor lowering`. The reached-signature
   boundary now prepares by-value parameter destruction. Newly published
   containment edges enter the same reached-owner worklist. Temporary scans
   include the selected copy's caller-owned class parameters. Repeated calls
   reuse the facts; an unused signature still emits nothing.
