## Completed delegation group and architecture review

Own-class mem-initializers, including class aliases and qualified names, select
constructors through the existing overload/conversion engine. Delegation is the
only mem-initializer; a selected target chain cannot lead back to its owner.
Diagnostics retain the C++ text, location and selection-before-cycle precedence.
An explicit delegation initialization context preserves constructor selection
for same-class arguments instead of taking ordinary object copy-elision paths.

A unit-owned optional `Delegation` stores a compact selected `ConstructorId`,
original `Initializer` and original argument-list/ExprId identities. Selected
conversions and defaults remain on the existing semantic facts. Delegating
plans leave their base/member actions empty and skip separate subobject
access checks. The next declared target body may be analyzed later without
reparsing or speculative body work. Cycle traversal follows only already
recorded delegation edges, matching the C++ owner; no whole-program retry or
native recursion is added.

Lowering consumes that edge, passes the current complete/base entry variant
and existing `this` address, and uses the ordinary constructor call path.
Argument temporaries end at the initializer's full-expression. Parenthesized
and braced forms preserve the C++ segment boundaries, including the braced
list's selected-constructor throw query, nonthrowing call results, throwing
destructors and caller-destroyed by-value parameters. A small call-temporary
enum retains the call-result/destructor summary. The new nonthrowing segment
state is introduced only by this initializer path.

Only after target construction and temporary cleanup complete does a typed
`CompletedObject::Whole` cleanup become active. It destroys the direct `this`
address using the constructor entry's complete/base destructor choice,
including detached body-unwind continuations and destructor terminate guards.
It does not substitute a base/member offset projection for the whole object.
Declared nonthrowing constructors include their delegate and written arguments
in the existing definition guard query.

Namespace-scope root demand iterates the existing ordered demand list, emitting
a used delegating constructor and the target its emitted body calls. Unused
constructors remain unlowered. Body, block, cleanup and temporary state stays
owned by one lowering `Function`; program output keeps only typed LowIR and
entry aliases. No optimizer, register allocator or native-generation code is
changed. No unsafe code, dependency, process/environment access, text transport,
fixture recognition or fallback implementation is introduced.
