- `specialized_classes.rs` selects an existing canonical class EntityId from
  typed lookup, checks dependence, definition state, class key and namespace
  in C++ order, then analyzes the explicit definition's own parsed ClassSyntax.
- `instance_definitions.rs::Definitions` owns sparse explicit membership and
  definition state. An explicit declaration records Done without pretending
  the class is complete. It blocks primary copying; a later explicit body
  completes the same shell. Reentrant and already-instantiated definitions
  retain their existing guard states.
- `declarations.rs` routes template-id definitions and lone declarations to
  this owner before ordinary class lookup. Explicit member classes bypass
  copied-member deferral. The ordinary class body supplies injected names,
  layout, bases, enums, members and virtual facts.
- `analyzer.rs`, `explicit_specializations.rs`, `function_names.rs` and
  `template_context.rs` separate SpecializationMode from checked introducer
  nesting levels. Heads consume the mode, ordinary members see ordinary
  mode, and required instantiation and errors restore the caller's context.
- `explicit_classes.rs`, `explicit_instantiations.rs` and `lowering.rs`
  retain ordinary member root flags independently of body demand and exclude
  inline ordinary members from roots. Explicit-class extern instantiation
  does not suppress members. Duplicate/definition-before-extern rules remain.
- `inheritance.rs::derived_class_conversion` and `scalar_conversions.rs`
  demand only the distinct derived class queried by value, reference or
  pointer conversion. Class completion supplies its base edges; standard
  conversion records keep canonical TypeIds and retained base paths.

All responsibilities are mapped in `source-map.tsv`. Class identity and ABI
arguments remain the existing primary EntityId plus canonical TypeId vector;
this group supports type-argument specializations, not textual value keys.

for the selected class. Template parsing remains once per source unit; the
