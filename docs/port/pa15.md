### Findings and fixes

1. **Canonical enum redeclarations:** an out-of-class dependent underlying
   type using a renamed template parameter was compared by its raw TypeId.
   `enumerations.rs::redeclared_enum` now compares canonical underlying types,
   retaining scoped/fixed/kind disagreement diagnostics. A late primary enum
   definition can drain its waiters without replacing an already specialized
   enum. Regression: `300-audit-dependent-enum-redeclaration.t`, including a
   sibling specialization and negative/successor values. Additional protected
   probes check unsigned boundaries, narrowing rejection and different heads.
2. **Deletion versus body definitions:** `Definition::Deleted` incorrectly
   participated in duplicate-body checks for explicit specializations. C++
   passes deletion separately. The explicit owner now distinguishes a body or
   defaulted definition from deletion while retaining copied semantic defined
   flags and deleted availability. Regressions: `300-audit-member-forward-delete.t`
   and `300-audit-deleted-specialization-repeated.t`; probes cover deleting
   after an own body and later calls to deleted specializations.
3. **Implicit assignment identity:** explicit member selection bypassed the
   class-owned implicit assignment preparation used by normal lookup. It now
   invokes that owning query before named signature selection. The rejection
   matches C++'s `an explicit specialization after the member's instantiation`.
   Regression: `300-audit-implicit-assignment-specialization-bad.t`.
4. **Absent special members:** the no-match function-template path attempted
   an expression-only key for an implicit destructor and returned status 86.
   It now uses the typed declaration key when no declarator arguments exist,
   producing the C++ no-matching-template diagnostic. Regression:
   `300-audit-implicit-destructor-specialization-bad.t`.
5. **Shared type-argument resolution:** declaration specialization selection
   accepted only arguments already classified as syntax types, bypassing the
   existing parsed-id-to-type resolver. It now uses `template_type_argument`,
   including ordinary undeclared/access diagnostics, without implementing
   non-type argument binding. Regression:
   `300-audit-member-template-argument-lookup-bad.t`; positive probes cover
   alias arguments and qualified private member arguments.
6. **Declaration-only static storage:** stripping the empty template head in
   lowering lost the immediate simple-declaration marker. An ordinary static
   member of an explicitly specialized class then emitted zero storage for a
   specialization without an initializer. The declaration iterator preserves
   that marker; `globals.rs` applies the C++ emission rule. A sparse, private
   EntityId set in the unit's lowering `Symbols` owner records declaration-only
   storage independently of semantic redeclaration bookkeeping, so referenced
   declarations also survive the final invariant check. Regression:
   `300-audit-own-class-static-declaration.t`; `ordinary-static-reference` and
   `ordinary-var-specialized-owner` protected probes exercise referenced cases.
7. **Protected native-stack qualification:** a semantic declaration guard
   returned a locationless Limit diagnostic, which the protected comparator
   correctly refused to qualify. Declaration error propagation now attaches
   its real source location after restoring access deferral. The byte-budget
   guard and all thresholds remain unchanged. On a fixed 512-layer class
   input with a 1 MiB initial stack, `resource_probe.py` obtains `match: true`
   and `stack_qualification.passed: true`: both tools succeed at **16 MiB**
   with identical streams and LowIR SHA-256
   `2c3d728e2ef43e179481f85e30f008eb5ca1e2519db3b0fef6a0201ab80d4613`.
   The original exits remain 1, as required by the adapter. Initial diagnostics
   and rerun evidence remain in `A/stack-qualifications/`; their positions are
   not compared as language results. No depth/cutoff calibration was used.
