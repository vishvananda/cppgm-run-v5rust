### Findings and fixes

1. A variable specialization's first declaration supplies its constexpr fact
   as well as its type. Rust overwrote constexpr when a later explicit
   declaration supplied a definition, including a shell first named in an
   unevaluated operand. Protected pointer-valued probes rejected where C++
   succeeded. A private typed declaration descriptor now supplies both facts
   only when creating the canonical shell; later declarations retain them.
2. C++ explicit variable specializations without initializers do not perform
   default construction/destruction checks. Rust rejected omitted initializers
   for const, reference and deleted-constructor objects. The explicit path now
   checks only supplied initializers, while retaining namespace-definition and
   member-declaration state. Following this through storage emission also
   exposed an assumed constructor fact for a demanded class object. Lowering
   now consumes the explicit declaration's recorded omission through a private
   typed query; ordinary required-construction invariants remain checked.
   Demanded classes get C++'s zero storage without a constructor call;
   layout requests are deduplicated per object and demanding function. A prior
   unused inline body cannot consume the layout request needed by main, and
   a pure assertion or unused body does not force incomplete object layout.
   Initializer-use edges are activated only by storage demand and pruned by
   completed scalar/array images: computing a constant pointer or bool does
   not itself demand the designated object's storage layout.
3. Explicit auto specialization deduction ran only in semantic modes. Types
   mode left the shell unresolved and diagnosed a later use as a self-reference.
   Auto deduction now belongs to declaration formation, before the independent
   semantic initializer/storage demand. A unit test verifies the concrete long
   type, repeated canonical lookup, no static initializer and no storage/body
   roots in types mode.
4. When both a variable and a variable its initializer references were already
   pending, Rust could publish the owner first. C++ recursively defines the
   dependency before that owner. The lowerer now promotes such dependencies
   into the current definition's isolated queue, keyed by owner/target IDs;
   active-definition guards preserve cyclic address initializers. A promoted
   reservation also keeps initializer-demanded functions ahead of later caller
   requests without shifting unrelated queue nodes. Existing
   outer requests remain valid and skip storage that was already emitted.
   This fixes raw declaration order, independently of the course's relaxed
   top-level comparison.
5. Semantic dumps instantiated an ordinary fixed-type variable template's
   initializer just from an evaluated name, adding an unwanted demanded
   function definition. C++ waits for storage lowering or a constant-value
   read. Ordinary name typing now leaves that initializer untouched; the
   constant evaluator explicitly requests eligible instance values when read,
   including pointer/reference values. A unit test checks the not-started
   initializer and absent body/root demand; dump-mode probes check exact bytes.

### Architecture and behavior review

Traced a demanded variable specialization from parsed TemplateArguments through
canonical TypeIds and its primary EntityId to its hidden BindingId, initializer
state and bound frame. Its retained initializer AST is copied for concrete
facts once under the required instantiation context. Constants, arrays,
construction and storage remain independent facts. Lowering reads those facts
and ABI argument nodes directly, publishes each canonical storage symbol once
and emits in frozen demand order; it does not reconstruct template identity from a
rendered name. Auto declaration typing and omitted initialization now preserve
that separation as well.

Checked parameter kind/type matching, representability before target conversion,
signed/unsigned extrema, bool/enum conversion restrictions, dependent target
substitution using earlier arguments, and the source types seen by later
defaults before canonical conversion. Assertion conditions type all operands,
record contextual bool conversion, and then evaluate; skipped constant
operations do not bypass typing. Diagnostic spelling/order and raw artifacts
are compared by the protected probes. Ordinary and synthesized value/type
identities remain distinct, including the frozen positional index truncation
and conservative BoundNames depth rule.

Partial selection uses per-primary positional indexes, ordered selected lists,
structural deduction plus substituted-list equality, and immutable entity-pair
ordering memos. Candidate work visits selected lists and type DAGs, not an
unrelated global registry. Reviewed canonical shell/default reuse, member
primary identity, renamed outside frames, constant-versus-storage demand and
recursive initializer states. Result paths restore temporary template,
argument, unevaluated and lookup contexts; required initializer errors remain
errors, and failed implicit initialization removes its in-progress state.

The layout dependency queue is unit-owned, advances only new object/owner
pairs, and follows recorded initializer edges or completed static images in
source order. It neither eagerly demands all template initializers nor scans
the specialization registry. The lowerer's dependency-promotion pairs and
active set have its unit lifetime; each definition restores its prior owner
and pending queue through Result completion.

No fixture recognition, oracle delegation, subprocess implementation, source
reparsing, unsafe code, new dependencies, broad lint suppression, mechanical
split or new global scan was found in the reviewed changes. Copies retain
private instantiation facts or short canonical-ID argument snapshots, rather
than cloning all visible environments. Frontend and per-function LowIR/backend
ownership remain as before; optimizer/register allocator policy is untouched.
This audit concerns the supported source-to-LowIR checkpoint. PA34 source/object
mapping, fresh generations and path-identity proof remain due at PA34.

### Findings and corrections

1. `lower_evaluated_pointer` strips parentheses when finding a constexpr
   pointer value, but the caller evaluated a member's receiver only when the
   original outer node was a member. `(get().pointer)` and `((get().null))`
   therefore lost the call and its side effects. The lowerer now normalizes

   original receiver. Frozen `expression_lowering.cpp::expression` evaluates
   that receiver after materializing the constant address and before returning
   the pointer. Both nonzero-offset and null forms retain that exact order.

   it does not expand the parameter's type. Rust instead called ordinary
   `pack_expansion_type`, rejecting `int*... P` and `int&... R`. It also

   ellipsis positions. A typed declarator option suppresses only this root's
   expansion, without editing or cloning syntax. Nested function parameter
   clauses keep their own declarator options. Defaults still diagnose exactly
   `a template parameter pack with a default argument`.

   expression-result view, then overwrote it with the ordinary call printer's
   declared result. `operator const bool()` consequently printed a const bool
   prvalue where C++ prints bool. Conversion projections now retain the
   recorded result/category; ordinary calls retain their separate declared
   result presentation, including references. This consumes the selected
   typed conversion edge without another lookup or semantic decision.

   read. Template values with an unknown overload target also recognize a

   argument conversion still enforces owner/type qualification, integral-zero

   identity/storage remains outside this completed null-only group.

   These avoidable copies are removed: private typed store access reads one
   TypeId by index before each mutation. Only the required canonical converted
   pack and generated frame bindings are owned. Existing query-owned element

### Findings and fixes

1. **Defaults after a function pack used pattern positions.** A specialization
   such as `f<int,long>(1,2)` for `f(T... t, int n = sizeof...(T))` lost its
   default, while a shorter expansion could expose the wrong slot.

   private default-pattern vector, exactly as C++ `specialize` does. Pack
   elements have no defaults. Availability uses that vector and declaration

   slot, with independent in-progress/complete states. Unused defaults and the
   primary syntax stay untyped. The ownership test checks three partitions,
   repeated-call reuse, correct positions and distinct demanded copies.

2. **Prototype function packs lacked concrete operand bindings and structural
   keys.** Trailing array bounds using `sizeof...(t)` lost a viable signature;
   `decltype(sizeof...(t))` also fell back to a concrete ABI type. Operand scope
   substitution now creates ordinary dependent element parameters and a hidden
   whole-pack alias, through `pack_frames.rs`, before copying the operand.
   Structural keys preserve the prototype's position, level and pattern type.
   `placeholder_mangling.rs` consumes those typed facts as `sZfp_` or `sZT_`,
   including template levels. No lowerer lookup, parser, concrete-type fallback
   or synthesized call argument is involved. Empty packs and renamed equivalent
   declarations retain their identities.

3. **Signature length errors escaped candidate substitution, and declared
   arity was checked too late.** Empty lockstep packs emitted a location-zero
   expansion diagnostic instead of dropping a candidate and reporting the
   final call failure; explicitly supplied mismatched packs also suppressed
   viable fallback candidates. Completed signature formation and explicit
   pack-parameter substitution now decline only typed immediate-context
   `Diagnostic`/`NonConstant` failures. Active keys are removed before propagation;
   required-instantiation diagnostics, limits and internal errors retain their
   distinct paths. Declared fixed arity/default availability is checked before
   a pack candidate can demand its return type. This prevents an impossible
   candidate from instantiating a deliberately invalid class definition.
