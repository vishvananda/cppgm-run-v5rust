Rust ownership and typed data flow:

- `explicit_specializations.rs` selects an own member by canonical class scope,
  ValueKey/signature or MemberKey, then reuses its EntityId. It counts implicit
  enclosing specialization heads through member classes and primary owners.
  Function-template specializations use the existing typed argument/deduction
  keys, now including member templates and their enclosing specialization.
  Ordinary member redeclaration attributes remain distinct from a function
  template specialization's own attributes. Hidden bindings retain access.
- `special_members.rs` routes explicit constructors, destructors and conversion
  functions through the same specialization checks, then records their own
  ordinary parsed bodies and constructor/destruction facts.
- `template_bodies.rs` bypasses implicit copying for own explicit bodies.
  `layout.rs` processes their demanded object/ABI boundaries without waiting
  on primary body demand. `virtual_members.rs` treats an explicit member
  template specialization as a redeclaration of the existing member facts.
- `explicit_instantiations.rs` reuses the member selector for ordinary member
  function instantiations, validates return type and instantiation provenance,
  then retains the existing independent extern/definition/root state.
  `explicit_classes.rs` skips already specialized functions in class-wide
  instantiation; a direct instantiation can still mark a non-inline own root.
- `variable_instances.rs` owns removal of only the selected static member's
  initializer-pattern link. A declaration without an initializer blocks primary
  demand without defining storage. Later own definitions retain the same
  EntityId. Already-started initializer demand rejects before repeated-
  initializer diagnostics. `declarations.rs` consumes this definition fact;
  `linkage.rs` owns the unchanged effective-storage-specifier classification.
- `enumerations.rs` accepts dependent underlying types in template patterns,
  preserves int pattern numbering and explicit target wrapping, and validates
  concrete underlying types normally. `enum_instances.rs` observes an already
  completed own enum when its primary-definition waiter is drained.
- `lowering.rs` separates copied semantic redeclaration flags from available
  own definitions and preserves explicit static storage under an enclosing
  extern class instantiation. `lower/mod.rs` emits only actual special-member
  definitions; declarations/deleted declarations do not synthesize bodies.

Responsibilities are mapped in `source-map.tsv`. No syntax is reparsed, no
rendered name is used as semantic identity, and no primary body is copied to
implement an explicit definition.
