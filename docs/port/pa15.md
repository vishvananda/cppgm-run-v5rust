- C++ `analyzer.cpp::template_parameters/non_type_parameter_type`,
  `class_templates.cpp::positional_parameter`, and `template_names.cpp` head
  shapes translate to `templates.rs`, `value_arguments.rs` and `types.rs`.
  Declaration bindings distinguish type and value parameters. Positional
  identity includes kind/pack/depth/index; head equivalence also includes
  canonical declared value types. Canonical entities publish their positional
  type once and retain their first immutable descriptor. Parameter types
  discard top-level cv, adjust arrays/functions and validate the frozen
  permitted-type categories; address argument formation remains a boundary.
- C++ `class_templates.cpp::template_argument/template_value/matched_element/
  converted_value/template_default` translate to `value_arguments.rs`,
  `template_names.rs`, `class_templates.rs` and `function_templates.rs`.
  Interned `TypeKind::Value` records canonical type and target `u64` bits.
  Existing checked integral arithmetic supplies values. Conversion checks
  representability, enum identity and scoped-enum restrictions; it never
  silently truncates a narrowing argument. Explicit function arguments convert
  before signature substitution. Class arguments and newly supplied function
  defaults retain source types while later defaults form, followed by the
  frozen full-list canonical conversion. Dependent target types substitute only
  earlier arguments. C++ `function_templates.cpp::deduced_values_typed/BoundNames`
  preserves exact deduced value types and its structural array-bound exception.
- C++ `template_placeholders.cpp` and `class_templates.cpp::substituted_scope`
  translate to `template_operands.rs` and the shared argument binding API.
  Type and value operand identities, equivalence tables and successful query
  memos stay separate even for the same structural expression. Fixed invalid
  values are checked at definition time; dependent values wait. Decltype of a
  value parameter retains its expression for signature ABI encoding. ExprIds,
  TypeIds, EntityIds, scopes and lookup limits remain typed facts on one parsed unit.
  Defaults retain a type/expression syntax sum. Concrete instantiations copy
  retained syntax for their own facts; no token/text replay is introduced.
- C++ `class_templates.cpp::instantiation_frame/bind_argument/value_binding`
  translates to the shared `value_arguments.rs` API and its class definition,
  function body, default, operand and out-of-class member callers. Concrete
  values bind fresh constant Enumerator entities; declarations retain
  TemplateValue identities. Dependent bindings name the argument entity.
  Out-of-class bridges compare source entity identity and include renamed
  value parameters. No frame overwrites a pattern parameter or constant.
- C++ `lookup.cpp` value-parameter-use tracking and `template_value` translate
  to the separate monotonic lookup counter in `analyzer.rs`/`lookup.rs` and its
  scoped consumer in `value_arguments.rs`. A concrete frame value still marks
  its template-id dependent for instantiation-context ADL. Separately,
  `template_arguments` context suppresses instance-static storage demand while
  typing a constant argument. `template_context.rs` and operand queries restore
  that state on success and failure. Ordinary evaluated uses keep their demand.
- C++ `lower/symbol_lowering.cpp::abi_type/declared_argument/
  declared_type_dependent/append_type_label` translates to `symbols.rs`,
  `placeholder_mangling.rs`, `specialization_labels.rs` and typed sema lowering
  queries. ABI literals, non-type parameter expressions, dependent value
  expressions and `Tn` parameter declarations consume retained semantic facts.
  Literal presentation preserves signed, bool and enum rules. The dump hides
  declaration value bindings and renders canonical integral argument bits.
