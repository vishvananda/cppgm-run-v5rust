## Architecture and Rust review

Traced a non-inline virtual key function and a demanded `std::function`/template
specialization from `driver/ast.rs::emit_preprocessed` through the shared parser,
semantic demands, lowering and `native/object_compile.rs::append`. The source
owner supplies one on-demand token cursor and one syntax tree. Parser attempts
retain bounded checkpoints, restore syntax/scope/scratch marks on rejection and
release retained tokens. Instantiation copies parsed patterns into owned stores;
it does not replay tokens or rendered text.

Entity/type/constructor/ABI/LowIR identities are typed. Function demand keeps a
first-use vector plus identity index; body/class completion has explicit states.
ABI cache keys include the canonical type, bound-pattern mode and template level;
function/name caches belong to one unit. Constructor upgrades preserve IDs and
publish completed subobject plans. Output queues, not hash iteration, determine
observable order. No library-private name shortcut or fixture recognition was
introduced. Runtime environment collection remains in executable boundaries;
the reviewed build-time host capture supplies configuration only.

At O0 the typed definition sink encodes one function and releases its LowIR;
MIR, placement and frame analysis end with that function. Unit-owned symbol,
section and relocation state survives until ELF serialization. Textual LowIR is
an explicit tool view, and the production source path never reads it back.
`finish_program` consumes lowering state before final native/optimizer work.
Target arithmetic uses explicit widths/wrapping; host sizes and compact store
bounds use checked conversion. Strict Clippy and the companion source audit
cover safe code, narrow lint expectations, file/function/nesting limits and
source responsibilities. No dependency, allowance or production path changed.
