- `sema/function_templates.cpp::deduce_for_call`, `Deducible`, `deduce_type`,

  signature in lexical order; a fixed call parameter participates only when
  its aliased target is dependent and deducible. Discarded alias arguments

  `alias_specialization`: retain discarded dependent arguments in stand-in
  specializations so substitution failure remains observable, independently of
  the canonical declared/aliased target type.
- `sema/type_table.cpp::qualified_anew` was consulted for the next cv boundary;
  no type-qualification change is included in this group.

Rust owners and typed data flow:

- `sema/function_templates.rs::needs_deduction` uses `aliased_type`, checks the
  target's dependence, then walks its canonical TypeId for deducible parameters.
  Previously it walked the shell's discarded arguments and could try to deduce
  a concrete `long` from an `int` call argument, rejecting a viable call before
  ordinary overload conversion. The API returns `Result<bool, Error>` because
  alias qualification and canonicalization use checked type-store operations.
- Both `deduce_function_call` and `sema/function_packs.rs::deduce_pack_function_call`
  consume that shared gate. Pack partitions, explicit prefixes, ordering,
  leading/trailing result substitution, default completion and selected
  conversion facts remain owned by their existing reusable semantic phases.
- `sema/alias_templates.rs` still owns shell identity, the aliased-target index
  and complete alias-specialization keys. Its new unit test distinguishes
  target-based participation from shell-based substitution: discarded parameters
  skip deduction, direct dependent targets still deduce, invalid discarded
  member arguments still fail substitution, valid arguments succeed, and repeated
  queries preserve bindings/syntax without emission demand.

Architecture review: canonical compact TypeIds cross the interface; no second
syntax tree, reparsing or text transport is added. The new check is query-local
and uses the existing iterative visited-type walk. Alias facts remain unit-owned,
private and immutable after publication; no new cache, invalidation, unrelated
lookup, whole-program worklist or speculative class/member/body demand is added.

Optimizer, code generator, register allocator, emission order and per-function

lowering symbol graph owners; this is an ABI encoding boundary, not another
alias deduction defect. Preserve exact constructor entry points and indices.

`integral_constant<bool,true>::value` is a readonly weak global initialized to

global demand. Do not materialize every class member or broaden body demand.
