## Completed receiver group and architecture review

Ordinary member designations retain an `ObjectArgument` with canonical TypeId,
value category and `ObjectSource::Implicit` or an original explicit ExprId/arrow
flag. Naming classes remain EntityIds. Parentheses share the existing dense
record. Implicit field designation qualifies the member with the method's
object cv, removes only const for mutable members, preserves reference-member
referents, and also handles unevaluated uses. `this` has the canonical qualified
class pointer type; static/non-member uses reject with the frozen diagnostic.

Member call analysis uses the existing indexed lookup and reusable candidate
scratch. It filters arity/default availability before forming the implicit
object sequence, ranks cv/ref conversions in the object's class, and ignores
the object rank when either candidate is static. Member lookup suppresses ADL.
The selected declaration, explicit argument conversions and selected-owner
object conversion/path are retained on the original syntax facts. Lowering
reads them without repeating lookup or overload resolution. Bare bound-function
use, address formation and implicit conversion preserve the oracle's checking
order and diagnostics, including its rejection of a static function named
through an object outside a call.

Required ordinary methods consume a hidden first pointer parameter with exact
`object_bytes`, store it in a function-owned `this` slot, then initialize source
parameters. Unnamed definition parameter/slot ordinals include the hidden
parameter; external declarations use ABI argument ordinals. `this` loads and
implicit field projections consume recorded offsets/reference-holder types.
Receiver effects precede call arguments. Static calls evaluate an explicit
object address but omit the hidden argument. Ordinary in-class/out-of-class,
cv/ref-qualified, nested, default-argument and reference-returning method
paths reuse the procedural lowering/emission pipeline.

ABI construction consumes typed class/namespace scope owners and member cv/ref
facts. Combined cv type qualifiers encode in the frozen VK order through one
ABI graph modifier, preserving substitutions. Only a root namespace named std
uses the std abbreviation; a class with that spelling retains its class identity.
Unsupported local ABI scopes still fail explicitly. Simple scalar assignment
fits the RHS before evaluating the LHS address, as the C++ owner does; this
preserves nested bool-member conversion/instruction order.

The existing emitted-function demand walk requests each required this-class
layout once. Implicit field designation does not complete unused method owners.
No token replay, second syntax tree, string semantic key, compiler subprocess,
unsafe/FFI implementation or new optimization was introduced. Candidate scratch
retains capacity only between queries; each body owns and releases its slots,
temporaries and LowIR. Optimizer/register allocator/backend sources are unchanged.
Class constructors/destructors, nonvirtual base layout/adjustment and local ABI
scopes are explicit next boundaries, not silent receiver fallbacks.
