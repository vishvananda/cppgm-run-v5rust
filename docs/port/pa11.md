Six findings were fixed in `6cdff3d`:

1. **Static receiver effects and bytes.** Static calls always loaded a pointer
   or computed an object address, including pure receivers. The frozen
   `side_effect_free` / `member_object` query skips pure names, member paths
   and subscripts, distinguishes an address from a volatile value read, and
   otherwise discards the original expression. A shared lowering query now
   serves static calls, data and folded-member accesses. The prior receiver
   ledger's claim that static calls always evaluate an explicit object address
   was incorrect and is superseded here. Effectful receivers still run before
   argument effects; the frozen 64-level semantic query cap is preserved.
2. **String-member helper eligibility.** Bare character-array string clauses
   incorrectly went through aggregate-array helpers, creating temporary slots
   and `copyobj` transfers. The frozen `helper_members` declines a non-list
   expression that directly initializes an array subaggregate. The corrected
   query selects final-member stores for bare strings; braced strings retain
   their helper form. Character widths and element stores use the shared typed
   character/array algorithms.
3. **Static function arguments.** A lone static member used as a call argument
   reached data-member lowering and exited 70 with `member without designation`.
   A read-only semantic API now exposes the recorded selected function identity
   to place lowering, preserving receiver effects, demand and function-address
   order. Separately, bound overload sets now fail candidate viability before
   target selection, matching the frozen `implicit_sequence` rule and exact
   `no viable function for the call` diagnostic. This preserves the oracle's
   rejection even for a bound overload set consisting of static functions.
4. **Defaulted trivial member dependencies.** An explicitly defaulted
   constructor could request its member facts before a trivial class/array
   member had a ready default-constructor plan. Defaulted definitions now
   prepare those direct dependencies; default selection walks defaulted child
   dependencies iteratively, with ready-plan reuse and active identity cycle
   detection. User-provided external declarations retain their demand boundary.
   Nontrivial recursive construction remains explicitly unfinished.
5. **Union rejection location/order.** For `S(): second(1), first(2)`, the old
   implementation diagnosed the second written initializer. The C++ owner
   diagnoses the second designated member in declaration order. The planning
   map now borrows original mem-initializers, retains their name locations and
   visits the member vector in declaration order. No hash iteration chooses
   the diagnostic. Duplicate-member checking and ordinary action order remain
   unchanged.
6. **Trivial subobject exception facts.** A trivial member constructor with
   an explicit `noexcept(false)` was omitted from the enclosing implicit or
   first-defaulted constructor's exception calculation, incorrectly emitting
   `unwind=no`. Plans now combine base/member constructor specifications and
   initializer throw facts. Explicit specifications use the existing deferred
   semantic query; implicit child plans supply their retained `nothrow` fact.
   Lowering omits trivial calls while consuming the correct enclosing metadata.

## Completed constructor-action group and architecture review

A private, unit-owned `ConstructorId` identifies each selected plan. It retains
canonical callable and dump presentation TypeIds separately, original member
EntityId/Initializer actions in declaration order, the hidden object pointer,
base/subobject IDs and nonthrowing facts. The source's special definition DeclId
and BodyId remain separate. First-declaration-defaulted constructors without a
written exception specification consume their subobject plan's exception fact;
an explicit specification, including `noexcept(false)`, takes precedence.

Default member initializers analyze with their canonical unqualified class
object context; that narrow context is restored on both success and failure.
Earlier fields, references, implicit calls and `this` use ordinary dense
original-expression receiver facts. Initializer throw queries reuse the existing
worklist and selected call/default facts; aggregate list prvalues visit their
required destructor edges. No name lookup or exception redecision occurs in
lowering. General constructor/temporary exception queries remain a boundary.

Local default construction consumes its selected plan and original default
arguments, with the object address before argument effects. Scalar/reference
constructor actions evaluate their value/binding before recomputing the member
address. Aggregate member and scalar-array actions use a typed `This` root:
each store recomputes the original path, with address-before-value order for
aggregate fields/array elements, exact pointer reloads, union untyped storage,
volatile memory facts, omitted zeros and nested reference bindings. Empty
parenthesized array initialization remains its original value-initialization
shape. Braced character-array data reuses the existing array lowering path.

The C++ `initialize_scalar_member` owner explicitly rejects a non-list array
member expression. That diagnostic is preserved, with the written body's
compound location or implicit body's zero location. Valid-language string-array
examples in `probes/character-array-default.cpp` and
`probes/character-array-parenthesized.cpp` reproduce this frozen lowering
limitation; both tools reject with identical status/diagnostics. No reference or
checker defect/instability was found and no contract was silently widened.

Lowering schedules `Entry::Function(EntityId)` or
`Entry::Constructor(ConstructorId, Complete/Base)` in one first-demand queue.
Explicit out-of-class definitions emit C2 before C1; demanded inline/implicit
C1 entries retain a separate C2 ABI alias. Already emitted base bodies suppress
that alias. Constructor ordinals follow the class's declaration vector. External
constructors emit typed signatures; inline definitions coalesce across units,
while unnamed-namespace constructors retain separate internal symbols, exact
object_root flags and local-object collision facts. ABI identities come from
canonical facts and typed graph terminals, never mangled-string reconstruction.

Implicit entries have no fabricated function EntityId or semantic AST. The
shared function builder owns hidden-object/source-parameter slots, locals,
blocks and temporaries and releases the body after streaming. Alias metadata
outlives that body in the typed program. All source paths stay parsed once;
there is no second semantic tree, text transport, whole-program polling,
subprocess implementation, unsafe/FFI code or new optimization. Optimizer,
register allocator and native backend sources are unchanged. Constructor and
ordinary function emission remain distinct from semantic analysis/demand.
