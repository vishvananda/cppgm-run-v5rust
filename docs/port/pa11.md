## Completed behavior group and architecture review

Plain object storage and aggregate arrays now consume original parsed syntax,
canonical types and recorded member identities/offsets. An implicit default
construction worklist completes trivial class/array subobjects once, keeps
member EntityId/ConstructorId edges, detects active identity cycles and retains
const-default facts. Child default-selection/access diagnostics use the frozen
implicit plan location zero; inaccessible/deleted member destructors delete the
enclosing constructor. No diagnostic text is parsed to derive these outcomes.

A trivial local class declaration emits its address without a constructor call.
A default-initialized trivial class array emits no initialization code. Nontrivial
construction and destruction remain explicit status-86 boundaries. Non-constexpr
class arrays no longer take the scalar image path. Aggregate arrays select the
C++ helper form only for its full/empty member shapes, with at least one full
element, and no evaluated self-reference; other arrays use computed enclosing
addresses and exact source-ordered scalar/member/element stores.

Helper calls retain reference address binding, scalar conversions, array argument
temporaries, object_bytes/pass facts, volatile initializing stores and ordinary
copyobj boundaries. Helper identities are typed class/member-count/cv keys,
separate from presentation labels; helper shape reuse is per unit. Each helper
body is built once, streamed, and released before the next helper. Definitions
follow the frozen helper-first demand order. No class body completion, name
lookup or overload resolution is repeated by lowering.

Namespace class storage preserves structured zero data and source declaration
order. The external-class-with-members empty startup step is reserved at its
first demand, with collision-safe symbol allocation. One typed empty startup
body survives across input units and is rendered once after the streamed
functions; it holds no frontend owner. Internal classes omit that step. Variable
unit locality follows nominal owners and compound types independently of source
internal linkage, so ABI `L` markers are not invented for an internal type.
Ordinary scalar/object/pointer shells allocate no locality scratch; shared
function type components use an iterative visited-ID walk. No member/body scan
or speculative whole-program work was added.

The existing lexer/parser, semantic conversions, typed LowIR stores/validator,
optimizer and register allocator remain the shared pipeline. No unsafe, FFI,
compiler subprocess fallback, fixture recognition, new optimization, textual
phase transport or second syntax tree was introduced. Local slots, helper IR
and temporary lowering state retain their function lifetimes. The retained
empty startup body is the explicit cross-unit initialization owner, not a
per-function backend retention change.
