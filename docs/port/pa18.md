Rust owners and typed data flow:

- `sema/template_operands.rs::Pattern` retains an optional canonical address
  `TypeId`. Structural interning, dependent-copy equivalence and declaration
  representatives include that target. Immutable pending levels inherit it;
  evaluation passes it to template_value, resolving the member function template
  from its required function signature. The concrete-target probe already
  substitutes the declared target before formation: the oracle retains that
  concrete target, rather than independently substituting a dependent target
  stored in an operand. This corrects the earlier ledger's proposed boundary.
- `OperandKind` distinguishes type/fixed and value formation. A fixed value's
  pattern owns a small memo of its last full requested target and canonical
  result, matching C++ fixed_value/fixed_target. Unknown-head formation refreshes
  it; later structural keying can reuse the linked-object designation without
  prematurely reading a nonconstant object. An ordinary fixed decltype still
  resolves to its actual type. These mutable memos do not mutate canonical types.
- `sema/value_arguments.rs`, `template_names.rs` and `function_templates.rs`
  carry explicit unknown-target context when no common parameter target is
  available. Definition-time argument-name checks use the same formation path.
  Ordinary defaults and substituted operands keep the frozen known-query mode.
- `sema/address_arguments.rs` recognizes linked integral/enum id-expressions
  through retained bindings. It preserves their Address(TypeId, EntityId) until
  a candidate binds a reference or reads the object's constant value for an
  integral/enum parameter. Retaining an unknown readable designation does not
  demand its initializer. Reading can demand only a const/constexpr instance
  initializer, then uses the existing narrowing and enum conversion rules.
- `sema/function_resolution.rs` reports a missing qualified operator as the
  positioned undeclared-name failure consumed by SFINAE, rather than a compiler
  invariant error. Existing access checks and overload selection order remain.

`sema/local_classes.rs` also consumes only a function specialization's own
canonical argument slice for argument locality, matching C++ argument_locality.
An internal-linkage object reference gives its function specialization internal
binding, including when that function is itself designated as an address argument.
This closes the raw internal-versus-weak metadata mismatch exposed by the const
reference probe; no optimization or symbol spelling is changed.

The existing unit-owned boxed operand/address stores own the new facts.
