### Findings and fixes

1. **Overloaded `operator&` mistaken for a built-in designation.**
   `address_template_argument` inspected the unary syntax without checking the
   recorded operator call. For a constexpr member returning null, Rust invented
   Address(int*, class-object), demanded the class object's storage and emitted
   an extra global. For a call returning a non-null pointer, Rust incorrectly
   accepted the argument while C++ rejected it. The C++ owner explicitly excludes
   kOperatorCall from the built-in-address path. Rust now checks ExprFacts.call;
   a call result passes through the existing constant interpreter and null-root
   validation. Null results produce the correct Value identity with no operand
   demand; non-null results produce exact C++ diagnostic bytes and location.
2. **Address locality omitted class context and C linkage.**
   The address-specific shortcut combined internal-linkage/template-argument
   flags with the entity's type locality. It missed an unnamed-namespace class's
   static member function and marked a C-linkage function with a private argument
   type unit-local when C++ leaves it external. Address locality now consumes
   the ordinary checked function or variable locality query, including enclosing
   class, own-local-result and C-linkage rules. Existing locality/unnamed-name/
   metadata callers propagate Result; invariant errors cannot become false
   locality answers. The existing iterative type DAG walk remains the shared
   type traversal, and no alternate signature parser or lookup was added.
