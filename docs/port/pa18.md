  `TemplateParameter` TypeIds with positional ParameterInfo at reserved depth

  distinct synthesized value and template-name stores. Call, function-address,
  conversion-result and class/variable-partial ordering share the same typed
  argument API. Repeated trials reuse immutable TypeIds; a synthetic type is
  never a class definition, object or emission root. A dependent non-type target
  remains unconverted, matching converted_value, rather than rejecting an
  invented class as an incomplete enumeration.
- `sema/declarations.rs::elaborated_type` consumes `Prefix::Dependent` directly
  and returns the existing canonical dependent-member binding. It never asks
  a dependent qualifier for a scope. Concrete prefixes retain ordinary
  elaborated lookup and class-key checks. For retained decltype operands,
  normal instantiation analyzes the retained syntax with a concrete qualifier:
  ambiguous inherited members and typedef names then fail in the immediate
  context, dropping that candidate. This follows the frozen representation;
  it does not add a separate elaborated-tag wrapper to dependent TypeIds.
- `sema/dependent_members.rs` retains the existing private qualifier/name index,
  canonical declaration representatives and incomplete-class publication rules.
  No failed member result or speculative completion is cached by this change.
  `sema/function_templates.rs` still owns structural deduction and ordering;
  the change supplies the correct dependent input identities to those routines.
