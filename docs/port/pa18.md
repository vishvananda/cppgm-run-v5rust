### Findings and fixes

1. Trailing-return analysis unconditionally cleared both enclosing contexts,
   even when its suffix introduced no member object. C++ replaces the context
   only for the declaration's own member-function suffix. Rust therefore
   rejected nested abstract function-pointer returns, including substituted
   const member signatures, and local static/friend declarations whose frozen
   behavior inherits the enclosing body. Five reduced probes showed Rust's
   this-outside-member diagnostic against C++ success. `declarators.rs` now
   preserves the enclosing signature/body for nonmember suffixes, installs a
   new object only for an own member suffix, and restores state before
   propagating any error. It preserves both cv identity and unrelated body
   control state without copying a BodyContext.
2. The invoke reuse guard compared a parenthesis-stripped name with the saved
   original callable ExprId. For `__builtin_invoke(((f)), args...)` it missed
   the retained designation and repeated name/template-id analysis. The guard
   now compares the already-recorded dense expression-fact root, in O(1),
   while preserving the original saved operand identity for recursive typing
   and restoration. No extra syntax walk, owning copy or new cache is needed.
   Rustfmt accounts for the surrounding call-expression indentation diff.
