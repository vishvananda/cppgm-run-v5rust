## Completed behavior group and architecture review

- The driver owns typed ordered `Source`/`LowIr`/`Object`/`Library` input kinds,
  byte-preserving paths, compile/link mode, output, library directories and
  preprocessing options. It implements course `.obj` output, direct and mixed
  source/object links, `-I`, `-D`, `-L`, `-l` joined/separate forms, supported
  target aliases, due benign flags, explicit empty output/library arguments,
  library search order, inode output alias checks and stale executable removal after a link failure. Accepted but
  untranslated host/optimized/LowIR object paths retain status 86.
- Every source gets its own source buffer, on-demand preprocessor, single
  syntax unit and semantic graph. Lowering consumes those typed facts through
  the existing demand queue. It never serializes/reparses LowIR to compile.
  Emit views retain their existing path. Environment and stack inputs stay
  in `dev/bin/` and reach the driver as typed values/options.
- `Program` privately owns one checked `DefinitionSink`. The native builder
  borrows typed Program data for one append, encodes that completed function,
  and the Program releases its LowIR body. Only encoded ranges/fixups and
  cross-function placement state survive. MIR and placement scratch die per
  function. The driver takes the sink once, checks its concrete builder type,
  and finishes pruning, data placement, symbols, relocations and groups after
  the frontend is dead. Native mode creates no text spans, deferred headers
  or family-order records; those remain exclusively in the text view. No
  backend retains a frontend pointer or borrow.
- Direct callees publish one typed signature/metadata record at first actual
  reference, allowing the backend to read forward call boundaries before
  unit-end declarations. Declaration emission reuses the recorded boundary.
  Canonical function/entry identities key the producer's existing maps;
  dense optional LowIR forward facts are indexed by `SymbolId`. This does not
  demand an unrelated body, scan the semantic registry or repeat lookup.
- Object-mode allocation forms remain link-time names rather than singleton
  role forwarders; `__builtin_abort` keeps its object identity. Selection,
  register placement, optimization policy and instruction encoding are the
  existing PA24 algorithms. No generated-code optimization was introduced.
- The ELF writer preserves ordered null/groups/content/RELA/symbol/string/
  GNU-stack sections, COMDAT relocation members, locals-first symbol remapping,
  original string offsets, NOBITS offsets, alignment and extended numbering.
  The checked decoder preserves ELF symbol numbering, ignores unloaded debug/
  unwind contents as C++ does, and retains common/absolute definitions,
  section/file symbol kinds, COMDAT membership and raw relocation codes.
- Static linking now includes common/absolute resolution, common BSS placement,
  section-symbol group signatures, ordered per-global/per-local GOT slots,
  exact supported x86-64 relocation widths/ranges and unsupported-type
  diagnostics. Target arithmetic uses explicit wrapping; host bounds and
  table/offset conversions are checked. No foreign compiler is a production
  fallback; host-built objects occur only in test inputs/probes.
- Preprocessing retains angle/quoted include facts and exact `-I` precedence.
  An immutable definition carries command-line provenance from a checked
  source-offset interval, so command-line definitions yield to later source
  definitions while normal differing source redefinitions still diagnose.

The callable symbol routines moved into their existing owning signature
module; this keeps `symbols.rs` within the authoritative file limit without a
mechanical split. No dependency, unsafe code, fixture, frozen source, checker,
protected acceptance policy or Ralph state was changed.
