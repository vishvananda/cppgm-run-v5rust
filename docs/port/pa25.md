### Findings and repairs

1. **A class statement-expression result bound to a local reference emitted
   cleanup blocks too early.** `lower/materialization.rs::class_temporary`
   excluded the pending construction region when a scoped reference's opaque
   block reported no operand temporaries. Frozen
   `lower/object_lowering.cpp::temporary_object` opens that region independently
   of the block's internal statements. Entering `ExpressionScope` then drops
   its empty marker; reusing that pending cleanup chain delays its placement.
   Rust now preserves this event sequence for the typed `ExprKind::Statement`.
   `400-audit-statement-expression-reference-result.t` checks the selected copy,
   extended lifetime, full object/link bytes, and runtime destruction counts.
   The baseline LowIR and raw objects are retained in the probe mismatch
   evidence; corrected views and objects match exactly.

2. **Semantic constant rejection used types-mode diagnostic wording.** The
   integral evaluator reported `not an integral constant expression`, and the
   pointer evaluator used its generic pointer-value fallback, for a statement
   expression. Frozen `sema/constant_expressions.cpp` rejects that expression
   with `an expression that is not a constant expression`. The typed integral
   and pointer dispatches now preserve those bytes; floating rejection already
   used them. PA25 executes integral and pointer rejection regressions, and
   the extra probes cover floating rejection too. Functional-call constant
   casts now live in the existing `constant_call` owner, before its skipping
   branch, retaining the previous conversion/evaluation order and keeping the
   expression dispatcher within the ordinary source limit.

3. **A nested default hid its declaring class's deferred constexpr body.** The
   adjacent boundary retained by the accepted default group is repaired.
   `sema/template_context.rs` swapped the declaration-owned definition index
   out along with query scratch. An enclosing-class member-template default
   calling `size()` before class completion therefore missed the copied member
   body and tried an original definition in the wrong argument frame, reporting
   an undeclared `T`. Frozen `class_templates.cpp::InstantiationContext` retains
   definition availability, and `constant_evaluator.cpp::constexpr_definition`
   demands the selected copied member. The index now remains visible across
   nested queries while their transient queues stay isolated. The earliest
   owning PA16 lane executes `400-member-constexpr-template-default-demand.t`;
   PA25 executes an additional object/link/runtime regression. A typed invariant
   test observes two distinct successfully memoized bodies for int/long frames,
   canonical reuse of the int class, and an unstarted unrelated member body.
   Supplemental probes also cover member-template constexpr calls, dependent
   earlier arguments, original completion controls and failing body diagnostics.

4. **Block-pack discovery searched every preceding local shadow per name.**
   `syntax/cloning/expansions.rs::Expansion::length` linearly searched the shadow
   vector, making a block with many distinct locals quadratic even though most
   names are unrelated to packs. An indexed `NameId -> Shadow` map now provides
   lookup; a source-ordered undo log preserves nested hidden/deferred states and
   removes entries on scope exit. Collection restores its shadow mark before
   returning either success or a copy error, alongside tree/rename restoration.
   The explicit `Shadow` enum distinguishes hidden names from deferred packs
   and absent entries. A unit invariant verifies nested restoration. The
   existing collector still uses the owning syntax cloner's lexical walk,
   marks/rewinds its query copy as C++ `pattern_packs` does, and excludes nested
   expansions. It introduces no second parser or lasting syntax tree.

## Completed behavior group and architecture review

- The driver owns typed ordered `Source`/`LowIr`/`Object`/`Library` input kinds,
  byte-preserving paths, compile/link mode, output, library directories and
  preprocessing options. It implements course `.obj` output, direct and mixed
  source/object links, `-I`, `-D`, `-L`, `-l` joined/separate forms, supported
  target aliases, due benign flags, explicit empty output/library arguments,
  library search order, inode output alias checks and stale executable removal after a link failure. Accepted but
  untranslated host/optimized/LowIR object paths retain status 86.
- Every source gets its own source buffer, on-demand preprocessor, single
  syntax unit and semantic graph. Lowering consumes those typed facts through
  the existing demand queue. It never serializes/reparses LowIR to compile.
  Emit views retain their existing path. Environment and stack inputs stay
  in `dev/bin/` and reach the driver as typed values/options.
- `Program` privately owns one checked `DefinitionSink`. The native builder
  borrows typed Program data for one append, encodes that completed function,
  and the Program releases its LowIR body. Only encoded ranges/fixups and
  cross-function placement state survive. MIR and placement scratch die per
  function. The driver takes the sink once, checks its concrete builder type,
  and finishes pruning, data placement, symbols, relocations and groups after
  the frontend is dead. Native mode creates no text spans, deferred headers
  or family-order records; those remain exclusively in the text view. No
  backend retains a frontend pointer or borrow.
- Direct callees publish one typed signature/metadata record at first actual
  reference, allowing the backend to read forward call boundaries before
  unit-end declarations. Declaration emission reuses the recorded boundary.
  Canonical function/entry identities key the producer's existing maps;
  dense optional LowIR forward facts are indexed by `SymbolId`. This does not
  demand an unrelated body, scan the semantic registry or repeat lookup.
- Object-mode allocation forms remain link-time names rather than singleton
  role forwarders; `__builtin_abort` keeps its object identity. Selection,
  register placement, optimization policy and instruction encoding are the
  existing PA24 algorithms. No generated-code optimization was introduced.
- The ELF writer preserves ordered null/groups/content/RELA/symbol/string/
  GNU-stack sections, COMDAT relocation members, locals-first symbol remapping,
  original string offsets, NOBITS offsets, alignment and extended numbering.
  The checked decoder preserves ELF symbol numbering, ignores unloaded debug/
  unwind contents as C++ does, and retains common/absolute definitions,
  section/file symbol kinds, COMDAT membership and raw relocation codes.
- Static linking now includes common/absolute resolution, common BSS placement,
  section-symbol group signatures, ordered per-global/per-local GOT slots,
  exact supported x86-64 relocation widths/ranges and unsupported-type
  diagnostics. Target arithmetic uses explicit wrapping; host bounds and
  table/offset conversions are checked. No foreign compiler is a production
  fallback; host-built objects occur only in test inputs/probes.
- Preprocessing retains angle/quoted include facts and exact `-I` precedence.
  An immutable definition carries command-line provenance from a checked
  source-offset interval, so command-line definitions yield to later source
  definitions while normal differing source redefinitions still diagnose.
