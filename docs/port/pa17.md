## Completed coherent group and architecture review

Ordinary type/non-type **pack argument partitions in class and variable partial
patterns** now use the same formation, deduction and ordering machinery as
represented fixed patterns. This includes empty packs, fixed prefixes, repeated
pack consistency, function-parameter expansions, value packs, C ellipses and
function cv/ref qualifiers. It does not claim template-template or enclosing
owner substitution completion.

Formation rejects defaults before own-parameter lists, then checks the flattened
argument positions for non-trailing expansions and unexpanded packs before
checking deducibility. A template argument list containing a non-trailing
expansion is wholly non-deduced; a function parameter list skips only that
expansion. Named value placeholders contribute the parameter they name.
The borrowed flattened iterator retains no extra argument representation, and
the iterative visited-TypeId worklist handles shared/deep DAGs once per query.

Partial deduction fills undeduced packs with canonical empty packs, converts
pack elements through the ordinary argument matcher and confirms the complete
substituted list by canonical identity. Pair ordering substitutes a pack of a
unique **expansion**, not a scalar unique type, so a fixed argument cannot deduce
from an expansion and fixed prefixes order correctly. Existing per-primary
argument indexes and candidate visitation order remain authoritative.

Concrete class shells continue to carry primary identity. Selected partial
EntityIds and deduced TypeIds are recorded independently from definition,
layout, member-body, initializer and storage demand. Variable templates retain
that same separation. Existing immutable substitution environments and scoped
pack-element selection remain query-owned; no tokens are replayed, names or
rendered types used as semantic keys, or unrelated templates scanned.

Array structural matching descends into element cv, whereas whole-array type
parameter deduction removes only the requested cv. Array presentation labels
use the represented element once. Existing syntax, type, semantic, ABI and
LowIR ownership boundaries are retained. Optimizer/register allocator/native
emission policies and per-function backend lifetimes are unchanged; no new
optimization, dependency, unsafe, environment read, FFI, compiler fallback or
blanket lint suppression was introduced.

Two semantic store tests cover non-trailing expansion contexts and concrete
empty/nonempty partition identity with repeated completion leaving syntax
stores unchanged. Existing executed PA17 cases exercise the language behavior;
fixtures, checks, references and policy were not edited.
