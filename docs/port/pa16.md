## Completed behavior group and owners

- C++ `constant_values.h`, `constant_frames.h` and
  `constant_interpreter.cpp::initialize/publish/root_storage` map to
  `constexpr_frames.rs`, `constexpr_values.rs`, `constant_addresses.rs` and
  `constant_floats.rs`. Evaluation uses flat cells with private compact CellIds,
  canonical TypeIds, byte offsets and bit-field EntityIds. Successful class and
  array values detach into immutable declaration-owned snapshots. Their sparse
  index makes subsequent scalar/reference-member reads constant-time on average.
  No expression text or constructor body is replayed to read a published value.
- C++ `constant_evaluator.cpp::record_constant_initializer/variable_value` maps
  to `constants.rs` and `constexpr_values.rs`. Required constexpr aggregate
  initialization checks every scalar leaf and publishes only success.
  Self-addresses become the owning variable identity; other evaluation objects,
  automatic objects and thread-local objects cannot escape as static constants.
  Ordinary namespace probes remain separate from constexpr usability and fall
  back to dynamic initialization on core constant-expression failure.
- C++ `constant_construction.cpp::construct/initialize_from/string_array` maps
  to `constexpr_construction.rs` and `constexpr_objects.rs`. Class prvalues in
  aggregate initializers materialize once, strings initialize typed array cells,
  default class arrays construct every leaf, and defaulted constructors execute
  their typed subobject plans without requiring a parsed user body. Trivial
  storage copies and selected user-provided copy constructors keep their own
  paths; implicit nontrivial member-copy execution remains a next dependency.
- C++ `constant_statements.cpp::bind_parameters/returned/end_parameters` maps
  to `constexpr_calls.rs`, `constexpr_statements.rs` and `constexpr_frames.rs`.
  A direct class-result call constructs into storage allocated in its caller
  before parameter and block regions. By-value class arguments initialize
  independent cells through recorded copy selections; their lifetime ends on
  return even though caller temporary storage may remain allocated. References
  retain their own bindings and slot generations detect expired objects.
- C++ `analyzer_constexpr.cpp::check_constexpr_variable` maps to
  `literal_types.rs` and the declaration call site. Literal-type validation runs
  before initialization at the frozen declarator location. A completed image
  does not substitute for declaration validity.
- C++ `lower/constant_lowering.cpp::constant_data/constant_placements` maps to
  `evaluated_data.rs`, `static_initialization.rs`, `static_arrays.rs` and existing
  lower data/global owners. Completed values become stable offset-ordered scalar
  items, target floating bits, symbolic addresses, nested table pointers,
  supported combined bit-field units and padding. Default-initialized globals
  can consume those images; constructor demand and readonly metadata follow the
  frozen rules. Shared/split bit-field units still use dynamic lowering.

## Architecture and Rust review

Parsing remains once per source unit. Calls reuse analyzed bodies; snapshots
copy evaluated values, not ASTs or a second semantic tree. Canonical typed
identities cross the boundaries. The unit owns completed values; query frames,
parameter lifetimes and constructing-object overlays have explicit cleanup on
success and failure. The boxed sparse publication owner avoids inflating every
stack move of the semantic graph. Snapshot creation and subtree copying are
linear in owned cells; final image placement sorts by byte offset. No unrelated
entity scan or speculative whole-program work was introduced.

Lowering reads completed images and selected semantic facts. The optimizer,
register allocator and backend lifetimes were not changed. No unsafe code,
FFI/compiler fallback, fixture recognition, source reparsing, new dependency,
blanket lint allowance, environment read under `dev/src`, or protected-policy
change was introduced. The byte-budget stack guard and interpreter storage,
call-depth and step budgets remain real resource boundaries. Resource probes
use the protected adapter's match/stack qualification, never comparisons of
native exhaustion cutoffs or diagnostic positions.

The new ownership regression evaluates class parameters/results, published
copies and class-prvalue array elements repeatedly. It verifies independent
values, unchanged syntax size, stable completed-value cardinality, released
frames and an empty constructing overlay. Existing frame generation tests
remain in the quality suite.

### Completed responsibility and typed flow

The shared earliest divergence was dispatching analyzed overloaded expressions
as builtin syntax. C++ `constant_statements.cpp::operator_call/call_value/
call_place` supplies the production rules, consulted with
`constant_expressions.cpp`, `constant_interpreter.cpp` and
`constant_expressions.cpp::bind` and `constant_construction.cpp::initialize_from`'s related binding rules.

- `constexpr_calls.rs` consumes `CallForm`, selected `BindingId`, original
  operand `ExprId`s and receiver `BasePathId`. Unary, binary, assignment and
  subscript calls share normal invocation, typed parameters and caller-owned
  class-result storage. A postfix call binds its implicit target integer zero
  directly, with no synthesized literal or reparsed expression. The member
  owner query distinguishes ordinary member operators from free functions.
- Integral, floating, pointer, place, class materialization and discarded-value
  consumers use the recorded selected call before interpreting builtin syntax.
  Logical and comma operators evaluate their complete argument lists; builtin
  short-circuit and iterative left-spine evaluation remain separate. The spine
  only inspects completed operator facts where present; it does not demand
  facts during dependent type formation. Earlier constructor/template-pack
  checks exposed and verified that boundary.
- `constexpr_construction.rs` and reference binding consume retained converting
  constructor plans for class parameters, references and returns. The target
  class must match the conversion's owner, so binding the constructor's own
  argument does not apply its outer conversion again. Conversions do not
  mutate source expression types, allocate new AST nodes or rerun overload
  resolution. Caller temporaries, parameter objects and returned storage keep
  their existing region and lifetime owners.
- `constexpr_objects.rs::constant_arrow_operand` consumes the bounded retained
  `ArrowStep` list in order, including base projection, reference results and
  intermediate class prvalues. Data members, direct member calls and static
  member object effects use this same typed chain. Static functions evaluate
  their designation's object effects without binding a non-static receiver.
  Callable surrogates obtain a function address from their recorded conversion
  function and enter the existing indirect-call path.
- The newly reachable template subscript body required `__builtin_expect`.
  C++ `lex/gnu_builtins.cpp`, `sema/analyzer_builtins.cpp`,
  `constant_statements.cpp::builtin` and
  `lower/expression_lowering.cpp::call` define this dependency.
  `builtin_calls.rs`/`analyzer.rs` intern its identity once with the frozen
  `long(long,long)` signature. Constant evaluation visits both converted
  arguments in order and returns the first value. Runtime lowering fits the
  first operand, discards the hint for effects and emits no builtin call.
  `lower/symbols.rs` retains C linkage if its function identity is referenced.

The source map records these owners. Parsing and analysis facts remain unit
owned; invocation scratch is bounded by the existing evaluation owner. Arrow
walking is linear in its already bounded chain, and normal operator dispatch
adds constant work plus required argument/body evaluation. No unrelated entity
scan, program-wide invalidation, successful-fact recomputation, AST cloning,
new dependency, unsafe code or environment access was introduced. Existing
optimizer, allocator, code-generation policies and per-function backend
lifetimes are unchanged. The new Rust ownership regression checks distinct
repeated invocations, retained source expression count and released frame state.
