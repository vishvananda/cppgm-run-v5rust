## Coherent behavior groups

Copy capture now supports explicit/default captures of scalars, references to
objects/functions, class objects and arrays. Nested captures use the enclosing
closure storage. Non-mutable calls expose const copied members; mutable calls
preserve mutable access. Parenthesized `decltype` consults the potential member
without capturing it; ordinary `decltype` retains the entity's declared type.
Class constructor selection, deleted/access diagnostics and demanded bodies use
the existing copy owners. A completed capture prefix is destroyed if a later
copy unwinds; after successful completion the closure owns its members. Default
argument temporaries retain their scalar/full-expression or array/element
lifetime. Array copying preserves source-before-destination addressing, target
count multiplication, the eight-element unroll boundary, counted loops and
reverse destruction of constructed prefixes. Volatile source reads and closure
destructor course labels match the C++ owner.

Remaining dependencies include source `try`/handler/throw semantics and lowering,
RTTI/typeid/dynamic_cast, initializer-list interoperation, and the remaining
PA21 construction/full-expression exception groups. Captures composed with
source exceptions or RTTI still stop at those owners; this handoff does not
claim the complete assignment from passing fixture identities alone.

failures first report `extended semantic statements`, including the class-array
capture failure and multi-member capture unwinding controls. Port the frozen
`sema/analyzer_bodies.cpp`, `sema/analyzer_handlers.cpp`,

copy constructor demand, prefix ownership transfer, element default argument
lifetimes, the eight/nine array boundary and generated destructor labels.

completion, while body and emission demand stay at their lifetime sites.

stack qualification receipts, never native exhaustion depths or diagnostic
positions. No oracle, fixture, frozen reference, checker policy, optimizer,
register allocator or Ralph state is changed.
