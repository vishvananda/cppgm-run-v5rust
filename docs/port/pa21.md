### Findings, fixes and required regressions

1. **Throw operands acquired hidden return/condition exception behavior.**
   `throws.rs::initialize_exception` used `ExpressionUse::Value`, causing a
   selected noexcept copy/move to appear throwing and gain a spurious region.
   Frozen `exception_lowering.cpp::exception_object` opens an ordinary,
   non-discarded full-expression with no hidden return/condition context.
   The fix consumes the same retained constructor/conversion through
   `ExpressionUse::Initialization`. The local/parameter, parenthesized,
   nested-expression and polymorphic copy/move matrix now matches, including
   the previously failing `tests/general/200-source-base-ref-catch.t`.

2. **Expression and synthesized subobject copies published class tables too
   early.** `construction.rs` used call_special's table publication and
   argument-temporary notification for expression-selected call_constructor;
   `copy_construction.rs::call_copy_constructor` also published tables at its
   call site. The frozen object/copy owners demand the selected body there;
   that body publishes tables when its initialization needs them. The shared
   constructor entry now preserves those distinct policies, and synthesized
   copies reuse the existing address-bound, demand-only emitter. A polymorphic
   parameter throw exposed both table order and dependent base-copy/destructor
   function order. No emission queue sorting or output canonicalization hides
   the difference.

3. **Widening a nonthrowing temporary segment reopened an empty unwind region.**
   A noexcept exception-object copy with a by-value default argument exposed
   `lifetime_regions.rs::before_lifetime_call`: after dropping the segment floor
   and closing its region, it reopened unconditionally. Frozen
   `cleanup_lowering.cpp::before_throwing_call` calls open_region(false, true),
   which leaves an empty chain to the enclosing try. Reopening now requires
   objects above that try's floor, an active-handler temporary boundary or
   tracked ownership. Explicit handler-copy regions retain their owner.
   Comma/cast sources, throwing/nonthrowing default-argument destructors and
   nested active handlers match exactly after this fix.

## Findings and fixes (prior audit)

1. **Namespace-scope reference casts lost static relocations.** The frozen
   lower/global_lowering.cpp::static_lvalue follows a reference cast's operand
   and retained base/derived projection flags, including runtime-check casts.
   Rust's core constant-place query correctly rejects dynamic_cast, but was
   also used as the only relocation query. It emitted a startup cast instead
   of the frozen relocation, including for a cast whose runtime search would
   fail. sema/static_addresses.rs now owns the distinct typed static query,
   following original ExprIds, source-ordered reference images, member/base
   paths, dereferences and subscript/pointer offsets. Static initialization
   consumes it; core constant evaluation keeps its rejection. Chained aliases,
   member bindings, forward/dynamic sources and pointer initializers match.
   A cast updates the pointer's designated element before arithmetic, retaining
   byte stride after a cast to char*. Target offsets use explicit wrapping;
   layout and binding failures propagate as structured errors.

2. **Destructor inertness omitted the contained-object context.** Frozen
   lower/program_lowering.cpp::destructor_does_nothing distinguishes a
   polymorphic object's own destruction from its destruction as an inert
   contained subobject. The Rust cache used one boolean per function and
   treated every nested polymorphic destructor as observable. It emitted
   unnecessary subobject calls, regions and aliases in copied closures.
   lower/symbols.rs now keys inertness by (EntityId, contained) and propagates
   the contained context only across base/member edges. Own polymorphic
   destruction and observable user destructor bodies remain effectful.

3. **Capture copies published vtables too early.** Frozen
   lower/object_lowering.cpp::construct_from demands the selected constructor;
   its definition publishes any needed table. Rust shared call_special's
   eager table publication, adding virtual destructors to the worklist ahead
   of a nested closure's call operator. The shared constructor-call emitter
   now retains that explicit publication distinction. Address-bound copies
   use definition-owned tables; ordinary construction retains call-site
   demand. Function, runtime declaration and ABI alias order now match.
