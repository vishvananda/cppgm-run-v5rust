## Typed flow and architecture review

Source syntax is parsed once. Cast analysis consumes its original operand's
facts once; static forms pass those facts to the existing conversion owner.
Sparse expression-ID records retain compact source/destination class IDs and
whether the result is a reference. Parentheses resolve through the existing fact
alias store. No renderer, text round trip, synthesized expression or
lowering-time overload selection participates.

A runtime cast records function-owned class-information demand edges only when
evaluated. The existing event-indexed reachability scheduler prepares the
required layouts, vtable slots and selected bodies; dormant specializations,
nonvirtual unrelated member bodies and unevaluated operands stay undemanded. The
scheduler has one boxed unit owner, keeping its growing indexes off native
analysis frames. This is not per-node allocation. The dense expression record
keeps its previous size; runtime-cast facts are sparse.

Lowering consumes those selected class IDs, ready layouts and existing class
RTTI emitters. Runtime declarations have program-owned identities, exact C ABI
linkage/roles/signatures and no-return boundaries. Hint results are cached by
class-ID pair. The source algorithm's second query for one derived class takes
one bounded all-base snapshot; only the current derived class retains that
snapshot. A 65,536-path budget falls back to the ABI's conservative -1 hint;
this is the frozen hint algorithm, independent of native stack limits. Target
offsets wrap explicitly and negative hints preserve signed 64-bit spelling.

The cast's slot, blocks and temporary numbering belong to one function. The
reference failure retains the frozen raw no-return continuation and zero return.
Object fallback positions allocate their result holders after ordinary body
slots, before the function terminate landing; zeroing, guard-end markers and
returns retain exact placement. Procedural glvalue forms follow the C++ owner,
including its rejection of empty/braced class prvalues and direct one-operand
functional designation. Backend lifetimes remain per function.

Independent audit should trace an array upcast, a cv-rejecting identity cast, a
private-base hint, a reference cast in a class-returning noexcept function, a
cast-only class-template vtable demand, an unused nonvirtual member body, and
aliasing of parenthesized runtime-cast facts.
