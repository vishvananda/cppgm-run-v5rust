## Owners and production invariants

- C++ `sema/analyzer_declarations.cpp::symbol_attributes` and
  `semantic_unit.h::SymbolAttributes` → Rust `sema/symbol_attributes.rs` and
  `graph.rs`. One private unit-owned sparse store keyed by canonical `EntityId`
  retains weak identity and validated section bytes. Leading and nested
  declarator attributes are applied in oracle order after declaration and
  layout facts; redeclarations update the same entity. Function definitions,
  special members and simple declarations use this owner. GNU/standard spelling,
  type-site exceptions, ignored typedef weak/function section attributes,
  external-linkage requirements, static storage, TLS rejection, token-safe
  concatenated section literals and conflict diagnostics match the C++ rules.
- C++ `lower/symbol_lowering.cpp::function_metadata/variable_metadata/variable_section`
  → Rust `lower/symbols.rs`. Lowering reads these facts directly, sets weak plus
  replaceable metadata on ordinary functions, ABI entries and variables, and
  publishes the existing forward-global address policy. Section inheritance
  follows only the requested entity's explicit member-pattern or variable-template
  primary edges. The frozen explicit variable-template declaration path ignores
  its own weak/section attributes (C++ leaves `init.declared` null) and uses its primary's
  section; ordinary object redeclarations still retain their own section. Generated
  guards keep their independent storage; weak definitions retain the existing
  ELF replacement versus COMDAT distinction. The entry function keeps the
  oracle's strong entry binding.
- C++ `lower/local_static_lowering.cpp` → Rust `lower/local_storage.rs` and
  `symbols.rs`: sections belong to the object, not its guard; void guard calls
  have no result temporary and retain lifetime-region completion.
- C++ `lower/global_lowering.cpp` and TLS id-expression handling in
  `expression_lowering.cpp` → Rust `lower/globals.rs`, `thread_local.rs`,
  `thread_local_symbols.rs` and `mod.rs`. Shared initialization is selected by
  actual weak binding, including GNU weak objects. A weak TLS variable's
  initialization entry inherits replaceability; its guard remains shared.
  Own unpublished definitions need future wrappers, completed static definitions
  use direct TLS addresses, and only external declarations use optional `_ZTH`
  references. Generated helper views drain in completion order. Unit TLS guard
  byte accesses preserve the original untyped instruction facts.
- C++ `cppgm++.cpp::run_emit_lowir_mode` → Rust `dev/bin/cppgm.rs` and
  `driver/ast.rs`: `-g0` is accepted by the LowIR emit view; AST/type/semantic views retain
  their original unsupported-option rejection. A `.lowir` destination with
  explicit `-g0` selects the typed host-object view. The ordinary course view
  retains its existing lowering configuration. This closes the section controls'
  earliest driver boundary and permits exact source/object-half inspection.

Parsing still happens once. Attribute operands retain parsed `ExprId` identity;
only the attribute owner inspects section literal bytes. There is no semantic
lookup or text replay in lowering. Attribute queries never scan unrelated
entities, and normal declarations allocate no attribute record. Source and
semantic owners remain unit-local; typed LowIR alone reaches native emission.
The O0 definition sink, function-local MIR and backend lifetimes are preserved.
No optimizer, register-allocation or instruction-selection policy changed.
Existing named-section, relocation and object writers consume the metadata.
No dependency, unsafe code, FFI, compiler fallback, environment read in a phase,
reference/fixture tailoring or blanket lint suppression was introduced.
