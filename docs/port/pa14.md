## Typed data flow, demand and architecture review

A namespace function-template declaration is indexed by its `ScopeId`, typed
callable key, complete canonical `TypeId` (including the result), and optional
interned template-head `ShapeId`. Ordinary functions retain their result-erased
signature. Different return types, template parameter counts, and ordinary versus
template declarations no longer collapse into one entity. Equivalent redeclarations
update the existing entity's indexed binding in its original overload position.
The index excludes templates imported from another namespace while the ordinary
visible overload edges retain those imports. Class-local searches visit only the
named overload family and apply the same full-type/head-shape identity; a matching
import is hidden by its parameter signature and head shape, in the C++ order.
Qualified namespace definitions use direct signature probes, and both namespace
and class definitions require a matching declaration.

Redeclaration agreement has one callable owner and preserves return, deleted,
redefinition, linkage and constexpr diagnostics before default/head merging. A later
function-template declaration cannot add an ordinary function default, including
when its template head also illegally repeats a type default. First-declaration
function defaults retain original `ExprId` patterns on the canonical function;
a later parameter clause omitting a default cannot erase it. The original first
head retains the parameter-name environment. Defaults stay unconverted and
unevaluated until a specialization uses one; that demand still returns explicit
missing implementation. No unsupported successful body or default is synthesized.

Definition-time default-name work retains original clause/type/scope identities
and template depth. Ordinary members of a class template use the existing
source-ordered complete-class queue, with saved depth restored on Result paths.
As frozen `finish_members` does, default-only entries of member/friend function
templates stay deferred, including an undeclared name in such an unused default.
A lookup already stopped at a typed dependent qualifier does not select a member;
it still validates retained template-argument syntax. Other lookup diagnostics and
missing-specialization boundaries propagate unchanged.

The ownership regression in `sema/function_names.rs` proves distinct canonical
entities for ordinary and return/head-shape template overloads, index reuse for
renamed equivalent declarations, persistent defaults despite the latest clause
omitting them, absent default expression facts, absent root/body demand and
unchanged syntax expression/declaration slab sizes. Namespace identity probes
remain indexed; no unrelated declaration scan, global retry or invalidation was
introduced. All new state is semantic-unit or declaration-completion owned.
No new dependency, unsafe, FFI, compiler subprocess, environment read, fixture
recognition, reference answer or textual phase transport was introduced. Optimizer,
register allocator, lowering/emission order and per-function backend lifetimes
are unchanged.
