## Typed data flow, demand and architecture review

An unbound unqualified callee is checked at its definition only when all of
its argument association types are known. The bounded probe consumes original
`ExprId` syntax and returns `Option<TypeId>`; unknown is not an invented type.
It preserves C++'s eight-argument and 32-level semantic conservatism, including
assignment/postfix/address/indirection/conditional and other opaque forms.
Parentheses are stripped iteratively. Plain literals and `sizeof`, `alignof`
and `noexcept` use a fundamental association surrogate without evaluating an
operand. Unary/binary arithmetic probes require known arithmetic operands.
Existing canonical declaration types supply variable/enumerator/parameter and
functional-cast results. References are stripped where C++ strips them.
Types declared in a function/block, including their pointer/reference/array
wrappers and nested classes, remain unknown until instantiation. Reserved
implementation names and parser-internal coroutine names stay deferred.

The type-only ADL entry accepts an inline array of at most eight canonical
`TypeId`s. It seeds the same association walk that runtime calls use, visiting
only indexed associated namespace/class/base/hidden-friend edges. It checks
whether any function is found, without testing viability, selecting an
overload, publishing expression facts or conversions, or demanding bodies,
layouts or emission. Scratch content is cleared on Result paths while
capacity is reusable. No whole-program retry, scan or persistent result cache
was added. Explicit function template-id arguments validate their retained
syntax once; an id-expression the parser did not know was a type resolves
through its existing name node, without grammar replay. Actual non-type and
pack argument work retains explicit missing-implementation boundaries.

Fixed base checks retain the selected binding and qualifier from lookup,
check completeness/finalness in the original order, and enqueue access at the
base's own location. Failed checks settle against the complete base list in
the new class scope, using the existing declaration-local access owner.
Friend class-template declarations merge their compatible parameter heads
and retain the same canonical friendship identity before later definitions;
default template arguments and template-parameter redeclarations diagnose at
the C++ locations. This handles befriended private bases and protected bases
in either base-list order without a layout or member-body request.

The new ownership regression exercises successive type-only ADL queries and
checks empty scratch, absent concrete call/callee/argument facts, absent root
demand, and unchanged expression/declaration slab counts. Existing base-access
ownership regressions and supplemental friend/protected-base comparisons
cover access deferral. Compiler code remains safe Rust with structured Result
errors, compact identities and parse-once ownership. No dependency, unsafe,
FFI, compiler subprocess, environment read, fixture recognition, reference
answer, optimizer/register-allocator change or textual phase transport was
introduced. Emission order and per-function backend lifetimes remain intact.
