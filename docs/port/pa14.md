### Completed group and ownership review

For represented free-function type-parameter signatures and default syntax,
only a selected call's omitted parameters instantiate defaults, in parameter
order. Supplying all arguments, selecting another overload, naming a signature
or explicitly instantiating an unused function does not instantiate its unused
defaults. Extern suppression of a function's body does not suppress a default
that a call needs. Calls inside defaults may demand other defaults and bodies;
unevaluated calls still instantiate defaults without demanding the selected
function's body. Default evaluation runs anew at each runtime call even though
its semantic facts are computed once per canonical specialization/parameter.

A private unit-owned store keys InProgress/Complete state by `EntityId` and
parameter ordinal; failed entries are removed. Successful copies are published
on the specialization's ordinary default vector and consumed directly by
lowering and semantic views. The primary's expression stays untyped. Each copy
has fresh `ExprId`, name and type-syntax IDs in the existing flat slabs; source,
spellings and interned identities remain shared. No parser replay, pattern
redirection on expression reads or second semantic tree was introduced.

The default's introducing head/frame remains separate from a later qualified
or renamed function definition. The first head's ordinal is retained even when
a later redeclaration introduces a default. Caller body, lookup limit, default
scope, unevaluated/template/class depth, active head, initializing entity and
base-object context are restored after analysis, including failure paths.
Ordinary braced, scalar, pointer, function-pointer, reference, class conversion
and class-copy rules supply the actual parameter initialization facts.

Analyzer syntax access is now an exclusive borrow so a call can append its
copy synchronously. Readers that cross such calls retain compact IDs or local
Copy descriptors instead of slab references. Query argument snapshots keep up
to eight IDs inline; larger lists own a temporary contiguous vector. They copy
only the query's IDs, cost O(argument count), and die with the query. Constructor
initializer indexes similarly retain Copy descriptors rather than pointers
into an appendable slab. Existing algorithms, source/emission order, per-function
backend lifetimes, optimizer and register allocator remain intact. There is no
whole-program scan/retry, environment read, dependency, unsafe code, subprocess
implementation, fallback answer or lint suppression. One existing placeholder
ownership test moved into its owning `placeholders.rs` module after the borrow
adjustments pushed the general test file over its audited size cap; no audit
policy was relaxed and the test is still executed in debug and release.

### Algorithm, ownership and failure-path review

Friend references select from indexed named function sets, compare the whole
canonical declared type, and publish only hidden binding references to the
canonical specialization. Repeated grants reuse one entity; primaries and
siblings receive no grant. Rejected/defaulted/inline/ambiguous declarations
follow the existing Result paths and ordinary initializer checks. They request
no function default, body or emission. Class-template friend placeholders remain
patterns awaiting the unfinished containing-class specialization owner.

Signature keys retain primary `EntityId` and canonical argument `TypeId`s;
`InProgress` prevents recursive signature work and successful signatures are
memoized. Substitution failures remove their provisional entry before returning.
Body demand is separate: each entity enters a first-use queue once, has explicit
in-progress/complete state, and may append further demands. Undefined templates
retain declarations; signature-only friends and unevaluated uses request no body.
The definition's own head/frame and binding ordinal govern name lookup, including
renamed/qualified definitions and ordinary definition-time calls.

Body copies allocate fresh fact-bearing IDs into the existing flat unit slabs;
immutable source/spelling/identifier storage stays shared. Names and type syntax
with context-specific dense facts receive fresh IDs, as do local declarations
and classes. Nested list scratch rewinds on successful list completion; any fatal
copy/analysis error drops the unit, so partially appended nodes or an in-progress
body cannot escape as a successful graph. Temporary analysis sessions borrow the
slabs, move the same Graph, restore body/noexcept context on Result paths, and
release session scratch. Unit-owned ordinals, block linkage obligations and
complete-class conversion caches survive sessions because their keys do.

Storage/call/constructor/destruction boundaries are collected on the unit and
visited after the body queue drains. They follow reached owner edges rather
than retrying every declaration per body. Operator candidates reuse ordinary,
member and ADL indexes; ties and duplicate builtin exclusion inspect canonical
primary identity. Postfix deduction never manufactures a zero as a deduction
source. Losing candidates do not demand bodies. Lowering consumes recorded
calls/conversions/body IDs and ABI arguments; weak emission remains independent
of inline preference. Source order, first-use demand order and final emission
order remain explicit and deterministic.

No fixture-specific behavior, oracle delegation, duplicate parser, global
registry scan/retry, copied visible environment, unsafe path, blanket lint
suppression, mechanical split or backend lifetime change was found in the
reviewed increments. The new printer projection is a local Copy value and an
existing typed-edge lookup, not a second semantic tree. Numeric algorithms were
unchanged; unsigned wrap, cv-sensitive parameters, reference results, diagnostic
bytes and declaration/emission order were independently compared. Existing
optimizer and register allocator behavior is preserved.
