## Completed behavior group and architecture review

The fixed validator carries `Option<FixedOperand>`: a canonical `TypeId`,
value category, possible-null-constant flag and constant-expression flag.
Unknown names and opaque forms stay unknown. A dependent `sizeof` supplies
its fixed unsigned-long result type without computing a value, substituting
its operand, or demanding a class layout or body. Literal decoding consumes
existing typed token bytes. No type or expression is reparsed.

The seed walk uses analyzer-owned reusable scratch, emptied before recursive
validation. The fixed walk retains C++'s 200-level semantic conservatism;
this is not a native stack cutoff. Unary, binary, comma, assignment, subscript
and member checks preserve C++ diagnostic spelling, precedence and locations.
Both sides of logical operators and every conditional arm are checked, even
where optional constant evaluation would short-circuit.

Fixed calls retain at most 16 small optional operands in an inline array,
visit only the directly indexed ordinary overload set and use the existing
scalar/reference conversion implementation. Arity/default availability,
variadic calls, class-parameter conservatism, builtin/member/template
exclusions and unique-result reference categories follow C++. The validator
counts viable functions without selecting a runtime call or publishing
conversions. It preserves the oracle's conservative possible-null flag rather
than evaluating an integral expression to tighten it.

Semantic template patterns now run fixed validation and the existing name
worklist. Concrete return/condition/operator conversions wait for
instantiation. Local initializer names and initialization-scope counts remain
checked while concrete initialization and constant/address evaluation wait.
`Control::Loop` and `Control::Switch(Option<TypeId>)` distinguish a loop from
a switch whose target is still dependent; no invented concrete type stands
for that fact. Duplicate-default, initialization-bypass and lexical scope
checks retain their existing owners. Primary template syntax contributes no
ordinary emitted definition; an actually demanded specialization still reaches
its explicit missing-body boundary instead of silently dropping code.

The ownership regression checks unchanged syntax counts, absent concrete
expression facts and absent root/function demand after fixed calls, local
initialization and a dependent switch in an unused template. Query scratch
has no persistent result cache; type interning retains canonical ownership.
No new dependency, unsafe code, compiler subprocess, environment read,
fixture recognition, whole-program search, optimizer/register-allocator change
or textual phase transport was introduced. Per-function lowering/backend
lifetimes and code-generation order remain intact.
