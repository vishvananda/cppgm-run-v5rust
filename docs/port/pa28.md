## Completed coherent group: canonical ABI tags

The existing parsed `Attribute` lists retain first-attribute grouping and
continued operands. Analysis validates plain/u8 concatenated identifier tags,
interns them as compact `NameId`s, and publishes sorted unique slices on
private typed `EntityId` or inline-namespace `ScopeId` owners. Existing binding
ordinals identify redeclarations; a later declaration may repeat a subset,
but cannot add a tag. Instance data members/typedefs reject tags, static data
members retain them, and a completed class ignores later elaborated tags
only after operand validation, as the frozen owner does. Ordinary rejection
locations and ordering remain exact, including a lone class's name location.

Lowering consumes these facts through typed APIs. Specializations use their
template's explicit name tags; member classes use their pattern's. The common
ABI identity reaches ordinary methods, constructors/destructors, aliases,
RTTI/type names and virtual support symbols. Function results and variable
types contribute only tags absent from the underived name/signature. This
includes local statics and their guards, hidden inline namespace tags, and
C-linkage/global bare-name exceptions. Typed in-progress callable encodings
break local-result naming recursion without reparsing or speculative bodies.

`abi/tags.rs` iteratively walks canonical `NodeId` edges, caches sets of at
most eight tags per node/mode, and uses a visited query for larger sets.
Underived edges prevent derived tags from recursively contributing through
local function contexts. Written-scope mode excludes hidden namespace tags
inside local encodings. Query storage belongs to the ABI graph and is included
in its measured reserved bytes; it is reset with that owner.

The complete callable-encoding responsibility moved from `symbols.rs` to
`callable_encoding.rs` to keep the implementation file within its audit cap.
Its signature/entry/parameter order is preserved. No optimizer, instruction
selector, register allocator or backend lifetime policy changed. Syntax is
parsed once; stored semantic facts feed typed ABI nodes and LowIR directly.
No new dependency, unsafe code, compiler subprocess fallback, fixture
recognition or whole-program scan was introduced.

### Architecture and algorithm review

ABI tags remain compact interned `NameId` slices on canonical entity/scope
owners. The declaration path validates operands before publication and respects
first-attribute grouping, redeclaration subsets and error precedence. Explicit
and implicit naming consumes those facts through typed ABI `NodeId` edges;
implicit tags are subtracted from underived encodings, then written tags are
sorted by spelling. Hidden namespace tags and local written-scope queries
remain distinct. Callable context is saved/restored around fallible encoding;
in-progress local-result encodings are popped even on an error. The DAG query
memoizes small sets of at most eight tags and visits large-set edges once per
query. Scratch storage and caches die/reset with their owning ABI graph.

Traced a tagged class's methods/support symbols and the demanded tagged
`f<int>` specialization in `review-abi/function-template.cpp` from the retained
syntax through canonical entity/template facts, ABI identity and ELF. The
specialization uses its primary's tags and retained signature, without parsing
again or demanding dormant bodies. `review-varargs/va-template.cpp` separately
checks type-first syntax cloning/substitution and extraction facts. Expected
trait-query failures remove active cache entries; completed answers use full
class/kind keys, with class completion and special-member preparation preceding
the query. Local candidate vectors enumerate only the owning class's indexed
members; there is no whole-program search or successful-body replay.

TLS calls consume the existing wrapper `SymbolId` and typed pointer result.
The shared lifetime helper covers pending receivers, tracked regions,
nonthrowing results and construction completion without inventing a source
`TypeId`. Reviewed destructor registration, guard completion, temporary cleanup
and first-demand external initializer publication order. Construction state is
restored after successful completion; a failure propagates out of the function
owner rather than resuming lowering with partial state. No native ABI exception
was introduced for a wrapper call.

The builtin prefix is another source in the original pull stream; it is parsed
into the unit's existing tree, with separate absolute/source-relative origins.
Arrays retain written types while parameter objects retain adjusted typed facts.
Builtin operations, conversions and the parsed va_arg type-id cross into
lowering as IDs/facts. `va_start` checks but does not evaluate its second operand;
`va_end` preserves its address-only operation and `va_copy` operand/copy order.
Numeric conversions and byte/alignment arithmetic remain explicit. Extraction
retains exact GPR/SSE limits, whole-object overflow fallback, alignment updates
and partial-eightbyte copy order. No text is used to transport production IR.

Syntax and semantic graphs remain single unit owners; instantiation creates
only its demanded syntax facts. Lowering borrows them and emits typed LowIR.
The backend retains LowIR/MIR/object data rather than front-end identities;
function-local homes, lifetime state and MIR are reclaimed with that function.
The callable file extraction is a complete naming responsibility, not a
mechanical split. File audit and strict Clippy independently pass. No review
finding was dismissed because the original fixture count stayed unchanged.
