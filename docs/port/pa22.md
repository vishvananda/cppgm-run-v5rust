## Implemented behavior and architecture

`dev/src/sema/data_member_pointers.rs` owns qualified data-member designation,
member-pointer application and explicit cast facts. Existing canonical
`TypeKind::MemberPointer` identities retain the declaring class and member type;
anonymous union fields use their enclosing member holder. The address records
its selected `BindingId` on the original syntax facts, without typing an
implicit object. Reference-member/protected access and ambiguous-object checks
retain the C++ diagnostic locations and wording.

Application records a compact `BasePathId` and the cv-qualified result type and
value category: `->*` produces an lvalue; `.*` produces an lvalue or xvalue
according to its object. Prvalue class objects reuse existing materialization.
Class completion/layout remains an explicit demand attached to the containing
function; parsing, lookup and overload selection are not repeated in lowering.

`ValueConversion::MemberToDerived` records standard sequence identity and rank.
`scalar_conversions.rs`, `scalar_operators.rs` and `function_resolution.rs`
handle qualification, composite owners and less-derived-owner ranking.
`inheritance.rs` retains checked accessible, unambiguous, nonvirtual routes
only when a conversion is applied. Inverse casts retain a distinct typed cast
route; C-style casts waive access/cv only as the C++ interpretation permits.

`dev/src/lower/member_pointers.rs` consumes those facts. Data pointers use i64
member offsets and -1 null, including integer-zero/nullptr/value initialization.
Forward/inverse adjustment emits the oracle's null-test/multiply/add sequence;
qualified addresses fold adjustment only at the operand boundary. Comparisons
retain raw operand evaluation and subsequent adjustment. Contextual truth adds
one; comparisons use the null sentinel. The object's retained base route is
projected before the selected field index; zero base offsets emit no extra
index. Anonymous-member offsets and union/volatile memory facts are preserved.

`lower/types.rs` provides i64/i128 member-pointer storage views without changing
canonical types. i128 storage is a prerequisite, not a claim of implemented
member-function values or dispatch. `semantics_dump.rs` renders a data-address
operand using its selected declaration's name, preserving the written syntax
for other views. The address-constant query requires the prvalue address form;
an implicit read of a member-pointer field still loads its stored value before
conversion.
No new per-node payload, second tree, text transport, compiler
fallback, dependency, environment read or whole-unit traversal was introduced.
Optimizer/native code and register allocation were not modified. PA35 remains
inactive; no PA34 object/bootstrap equality claim is made.
