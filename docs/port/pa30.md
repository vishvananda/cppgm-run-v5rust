Source buffers, syntax/list stores and semantic facts have unit owners; edges use
compact IDs. Fact-bearing specialization copies are explicit first analysis,
not token replay or a parallel semantic tree. Environments share prior levels;
lookup and specialization caches use typed identities. Output order is explicit,
not hash iteration. Temporary query memos are function-owned over the immutable
semantic graph, with separate root/operand queries; scan scratch is reused.
Backend transient state ends per function, and no frontend ownership crosses
the typed LowIR boundary. The new fix adds no cache, persistent field, dependency,
lookup fallback, parser, unsafe code, lint allowance or implementation split.

Due compilation runs in Rust. The protected adapter invokes C++ only as an
independent comparator; the course harness's execution/evaluation roles remain
separate. Build-time empty-input host configuration capture is the protected
PA29 arrangement. No user compilation is delegated to a host or oracle process.
PA32's standalone optimizer entry remains a later assignment boundary, not a
PA30 implementation substitute. Missing/invariant results are never accepted
as normal rejection. Source/architecture and companion limit checks are required
in addition to Clippy.

## Findings and independent evidence

The entry fixture pass did not prove completeness. The independent combined
vector/deque/list/map/unordered-map probe compiled successfully in both tools
but produced different object bytes. The earliest divergence was an extra
exception region around nonthrowing constructor arguments. C++ `local_object`
applies its constructor-throw override only to its single-expression path;
Rust incorrectly extended it to a multi-argument initializer.

Reducing that case and varying initializer arity, constructor/call noexcept and
reference/value parameter ownership found a second discrepancy: the single
nonthrowing prvalue/by-value path fell through to caller-destruction forcing
after its ordinary expression query should have finished. Both control-flow
rules are corrected by `89d3b063`. No generated-code optimization was introduced.

The executed regression is
[PA12 parenthesized initializer control](../../pa12/tests/controls/parenthesized-initializer-nothrow-arguments.t).
PA12 is its earliest owner because it requires class return/pass-by-value and
temporary materialization; it observes exact destruction counts. Its protected
case receipt also compares complete LowIR. Frozen inputs/references are unchanged.

[Raw evidence](../../artifacts/pa30-full-audit/) retains the original mismatch
objects, reduced inputs/diffs and final receipts in `probes.jsonl`. The 33 focused
comparisons cover the initializer matrix/reductions plus independent container,
callable/tuple, algorithm/iterator, random/numeric, stream/exception, extern/lazy
body, overload/SFINAE and forwarding compositions. Negative controls compare
exact diagnostics for invalid vector conversion, tuple index, ambiguous partial
and shift width. All final comparisons match. `roundtrip.json` proves both
implementations produce the same heavy-header object through direct compilation
and the explicit `--emit-lowir -g0 -o ...lowir` / object replay path.

The independent probes encountered no exhaustion. Resource-limited probes use the
protected adapter's `match` and `stack_qualification` receipt if qualification
is needed: only exact successful shared larger-stack results qualify. Native
exhaustion cutoffs and diagnostic positions are not clone defects or calibration
targets. The genuine byte-budget guard and logical instantiation limit are unchanged.
