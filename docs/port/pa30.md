## Mechanism and ownership

- C++ `analyzer_construction.cpp::{initialize_object,initialize_class,allocation}`
  maps to Rust `sema/allocation.rs::initialize_allocated_class`. A selected
  glvalue copy/move constructor belongs to the allocated object. Publish its
  existing constructor plan and remove the source's separate temporary-copy
  action, retaining its copy selection, category and reference binding. Prvalue
  elision and genuine conversion/argument temporaries keep their existing owners.
- C++ `allocation_lowering.cpp::allocation` maps to `lower/allocation.rs`.
  Placement syntax does not itself open an eager empty cleanup region.
  Ordinary operand/allocation calls and live objects determine region starts;
  matching deallocation, null branches, arrays and initializer completion keep
  their existing producer/consumer paths.
- C++ `cleanup_lowering.cpp::may_throw` maps to `lower/throw_scan.rs`.
  Its subscript branch scans operands without counting the overloaded subscript
  call itself. Actual call emission still protects live objects. A throwing
  index operand retains its full-expression segment, while a plain subscript
  can use the frozen transient call region instead of retaining result spills.

The [source map](source-map.tsv) records these responsibilities. The
[architecture review](../../artifacts/pa30-placement-cleanup/architecture-review.txt)
traces the selected allocation action through temporary/throw queries and
lowering. No new cache, store, persistent field, syntax copy/replay, global scan,
backend policy, lint exception or external fallback was introduced. Output
order, typed LowIR and per-function backend lifetimes remain unchanged.
