## Findings fixed in the audited implementation

1. Constructor-cleanup and destructor-containment output walks demanded invalid
   template destructor bodies for **union variant members**. The frozen constructor
   and destruction-order loops omit those members. The new output-child query
   excludes them without changing property, access or deletion checks.
2. The same walks discarded array bounds and demanded a destructor for an
   **absent zero-length member-array element**. Output edges now exclude empty
   arrays; semantic element-property queries retain their original behavior.
3. Once that false demand was removed, constructor member-end bookkeeping asked
   for an unknown-bound array's storage layout. C++ `aggregate_lowering.cpp::member_end_bits`
   uses `ProgramLowering::size_of`, which returns zero for hosted zero-bound
   arrays. `lower/member_initialization.rs` now uses its existing typed size query
   at the three object/array member-end sites.
