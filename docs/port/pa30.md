## Mechanism and ownership

Resolving a `noexcept` specification can complete a class specialization and
analyze its nested template declarations. Those declarations' constant operands
have not necessarily been typed, even while the enclosing specification is being
typed. C++ `sema/constant_evaluator.cpp` chooses recorded entity/type facts from
the operand itself; `constant_expressions.cpp` handles already typed expressions.
Rust `sema/constants.rs` now applies that occurrence test to name bindings,
functional casts, unary results, conditional result types and types-mode
exception call/arithmetic facts. Untyped template operands retain ordinary
definition-time evaluation; already typed operands still require recorded facts.

The producer chain remains `exceptions.rs` → `exception_operands.rs` → class
completion/value-argument formation; no producer is forced to type template
patterns prematurely. Concrete specialization consumers use the existing parsed
body copies and typed demand. All eight formerly affected hosted fixtures now
emit objects; seven match exactly, and map subscript reaches an independent
object divergence. The new **PA15** control covers nested dependent and concrete
non-type arguments; a unit regression checks types/full-semantic modes without
publishing expression facts or growing syntax during untyped evaluation.

The [source map](source-map.tsv) records ownership. The
[architecture review](../../artifacts/pa30-constant-context/architecture-review.txt)
traces producers and consumers. Canonical IDs, parse-once syntax, explicit demand,
compact stores and per-function backend lifetimes are preserved. No allocation
policy, cache, persistent field, text replay, environment read, lint exception,
unsafe code, fallback implementation or backend/optimizer policy changed.
