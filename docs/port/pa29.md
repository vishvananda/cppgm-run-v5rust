## Completed coherent group: hosted preprocessing and probes

The earliest common divergence of the hosted preprocessing cluster was the
status-86 `-E` driver stub, before preprocessing began. The driver now selects
an explicit `DriverMode`, opens/checks the output in the frozen order, emits
`preproc N`, and borrows one source through `sof`/posttokens/`eof` at a time.
Multiple sources share invocation configuration and reset macro/counter state.
The GNU number dialect feeds the existing typed tokenizer directly; no syntax,
semantic tree, builtin-declaration prefix or textual transport is constructed
for this view. The extended floating dependency below remains explicit.

`HostedOutput` bounds text buffering at 64 KiB. Failed writes retain failure
while subsequent parsing still demands ordinary source diagnostics. Source
construction errors keep their unlocated diagnostic wrapper; demanded errors
retain source locations/include notes. Missing implementation and internal
errors retain statuses 86 and 70 rather than becoming language rejections.
Input/output identity, missing/nonregular sources, output-open failures,
source/object routing and invocation-shape precedence match the frozen owner.

`DriverOptions` carries explicit hosted, `LanguageStandard` and `FeatureModes`
facts. Ordered `-D`/`-U` definitions precede forced includes regardless of where
`-include` appears; pthread and optimization definitions precede the explicit
macro operations. Separate `<command-line>` and `<predefined>` source frames
preserve diagnostics and source-defined versus replaceable macro provenance.
GNU/strict host macro selection and exception/RTTI feature filtering consume
captured configuration. Non-default C++ compile semantic modes remain an
explicit status-86 dependency at the source compilation boundary; object and
LowIR inputs do not demand those semantic modes.

All frozen hosted probe families are registered together. Include probes read
raw ordinary string/angle header names; feature/extension and guarantee probes
read one raw identifier; warning probes require a string literal. They validate
closing delimiters and substitute only in controlling expressions, following
the C++ expansion contexts. Feature names accept the frozen optional surrounding
underscores, respect exception/RTTI modes, and share lexical trait membership
with builtin and identifier probes. Unsupported guarantee families report zero
through their complete family implementation, allowing header fallbacks to work.

Include directives and availability probes use the same cached file/path store.
Each source frame retains the directory where it was found, so include-next
continues the search even after `#line` changes its presumed filename. Probes
may cache a file but do not enter it, count an include, or expand its contents.
Header guards and once identities retain their existing ownership. Warning,
include-next and named variadic macro parameters remain hosted-only; ordinary
course preprocessing retains its grammar/rejection boundary. Named variadics
reuse the existing immutable parameter slots and raw comma-paste roles.
