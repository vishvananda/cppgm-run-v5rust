Completed behavior in this group:

- Scalar `if`, `while`, `do`, `for`, and `switch` use the C++ block allocation
  and placement order. If ends are allocated only when a branch reaches them;
  absent for conditions jump directly to the body. Source-sense comparison
  predicates and bare scalar branches remain exact. Declared conditions
  initialize their scalar storage, read its original type, then consume the
  recorded promotion for switches or floating truth test for branches.
- Switch labels are scanned in source order through their own body, excluding
  nested switches. Converted case values are published once by analysis in a
  dense original-StmtId store and read through the private typed facade.
  Break uses the nearest loop/switch; continue finds the nearest enclosing
  loop across switches. Case fallthrough, nested case labels, and labels in
  otherwise unreachable substatements retain C++ ordering. Label reachability
  is memoized per function. Unreachable scalar declarations retain storage
  without evaluating an initializer, for labels that later enter their scope.
- Built-in logical conditions branch directly, with outer RHS blocks allocated
  first and placed innermost first. Left logical chains are iterative. Value
  logical operations preserve i64 result slots, normalized RHS truth,
  shortcut blocks and literal deciding operands. Void conditionals evaluate
  effects in `discard_cond_*` blocks without void slots or values.
- Scalar prefix/postfix increments and compound assignments compute each
  supported place once. Compound operations consume recorded operation/count
  TypeIds; load, RHS evaluation/conversion, LHS conversion, arithmetic and store
  retain the oracle order and typed/nowrap/volatile facts. Address formation,
  scalar dereference, assignment and comma places share that owner. A volatile
  update read as a value reloads the object; a discarded update does not.
  Scalar comma effects, ordinary discarded names/literals and void casts follow
  the C++ discard rules. No optimizer transformation was introduced.

## Typed ownership and architecture review

SourceBuffer -> on-demand preprocessing -> SyntaxUnit -> Analyzer/Graph -> borrowed read-only lowering views -> function-owned LowIR -> serialized definition bytes. Dense original-node facts provide declared/selected entities and conversions. EntityId/ScopeId/TypeId remain distinct compact identities with private stores; the lowering facade does not repeat lookup, overload resolution, parsing or constant evaluation. Phase modules do not read the environment or spawn compiler processes.

Local place maps and temporary/block/slot state die with their function. ABI types, names and symbols are memoized per semantic unit. Overload ordinals inspect only their indexed name family; traversal and demand order never depend on HashMap iteration. Backend and optimizer stubs are untouched, and this checkpoint introduces no generated-code optimization. The O0 text tool retains serialized output so input errors leave the destination untouched; it retains no completed function bodies.

The source and function audits pass without blanket suppression. Stack guards measure actual stack-byte distance using the typed host budget.
