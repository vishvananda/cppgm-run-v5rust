Completed behavior and invariants:

- Namespace arrays consume analyzed scalar images with original TypeIds,
  converted integral/enum/floating values, entity or literal address roots and
  target byte offsets. Subaggregate braces and omitted elements retain C++
  item order. Missing arithmetic elements are scalar zeros; pointer/nullptr
  zero bytes coalesce. Character array images retain every padded scalar code
  unit. Structured globals state a storage type only when their contents imply
  insufficient alignment. Const nonvolatile arrays are readonly.
- Literal addresses refer to internal readonly backing arrays. A unit shares
  equal code-unit images of one LowIR unit type, with monotone program literal
  numbering. Automatic scalar arrays use the C++ shared readonly image and
  copyobj form only when eligible; local storage remains distinct. Dynamic, automatic-address and
  volatile initializers retain ordered element stores. Multidimensional locals
  descend row addresses, keep scalar array_element projections and the separate
  ArrayElement conversion context; eligible constexpr images retain the copy
  form. Omitted bounds use already completed semantic TypeIds.
- Array decay uses the existing address or computed place, including unknown
  bound extern arrays without demanding their layout. Subscripts consume the
  recorded commuted flag and evaluate the pointer before the raw written index.
  Scalar projections keep their storage type; subarray projections widen and
  byte-scale the index. Pointer addition/subtraction, compound updates and
  prefix/postfix steps keep source order, additive literal conversion rules,
  target i64 scaling and subtraction negation. Differences retain the exact
  shift or division by element size. No optimization or register allocator
  change was introduced.
- Conditional scalar/array glvalues store the selected operand address in
  condaddr slots with the C++ block creation and placement order. Volatile
  reads, assignment/prefix-update values and source-side effects continue to
  use their typed place facts. Reference binding and class temporary lifetime
  remain separate dependencies.
- Streamed global publication order is independent of symbol-reference
  allocation, preserving literal-before-owner data. Replaced extern records
  are filtered by the symbol's current compact GlobalId; forward declarations
  across units disappear after definition. Array ABI modifiers consume typed
  bounds/elements, with qualifiers on the element rather than duplicated on
  the array wrapper. Storage bounds multiply iteratively with checked target
  byte sizes and alignment.

Findings fixed in `e044d7a` (each reproduced through the protected adapter with
matching successful exits but differing generated bytes before the fix):

1. `conversion_lowering.cpp::WideningFolds` excludes CompoundAssignment from
   signed literal widening. Rust incorrectly folded `long x; x += 2` and its
   multiplicative/bitwise/shift siblings. The context now preserves explicit
   sign extensions. No target arithmetic or nowrap policy was changed.
2. `expression_lowering.cpp::arithmetic` retypes a shift count after both
   operands and their ordinary conversions. Rust omitted this for mixed
   widths, emitting an i64 count in an i32 operation. It now consumes the
   expression's recorded result TypeId for that final conversion. Bool counts
   and the reverse i64/i32 boundary also match.
3. `function_lowering.cpp::integer` sign-extends a 64-bit image into the complete
   LowIR literal. Rust's switch producer zero-extended it, printing negative
   cases and unsigned high-bit cases as positive 64-bit magnitudes in an
   untyped context. The producer now extends the converted case image exactly;
   semantic case evaluation still happens once in its owning dense store.
4. `expression_lowering.cpp::size_query` materializes `sizeof`/`alignof` values
   with `const`, and arithmetic beside a size query uses BesideSize literal
   folding. Rust emitted bare immediates and ordinary widening instead. Both
   conventions are fixed. The discarded-query rules are kept separate:
   `sizeof` materializes a const, while discarded `alignof` emits nothing.
5. ABI callable types used source parameter qualifiers, producing
   `_Z1fKiViKPi` instead of `_Z1fiiPi`. Lowering-mode function suffix publication
   now memoizes canonical callable types once; its read-only type facade
   exposes the canonical parameters. Parameter bindings retain source cv for
   their body accesses. Direct, indirect and uncalled qualified definitions
   all match without lowering reconstructing types or altering type identity.
6. `function_lowering.cpp` initializes parameters through an unqualified Place.
   Rust applied the parameter object's volatile marker to prologue stores.
   Prologue initialization is now ordinary typed storage; body loads and writes
   retain the source qualifiers.
7. `discard_lowering.cpp::{discard,discard_to_void}` distinguishes ordinary
   discarded indirection (evaluate the place only) from the course's read of a
   nonvolatile scalar glvalue cast to void. Rust read the former and omitted
   named-object reads in the latter. The shared discard owner now implements
   that distinction, retains volatile reads and effects, and does not reload
   assignment/prefix-update results merely because they are cast to void.
