## Responsibilities and mechanism

Consulted the handout, contract, spec and conversion plan, then frozen
`lowiropt.cpp`, `cppgm++.cpp` invocation/emission owners,
`driver/toolchain.cpp`, `opt/{optimizer,inliner,constant_propagation}.cpp` and
their typed interfaces. Detailed ownership stays in [source-map.tsv](source-map.tsv).

- `driver/lowiropt.rs`, `bin/lowiropt.rs`, `lowir/{mod,validator}.rs` now route
  ordinary O0/O1 requests through the shared typed reader, optimizer and writer.
  Help/batch precedence, byte arguments, required/repeated options, checked
  decimal inline limits, output errors and optional final validation follow
  the frozen owners. Telemetry and per-pass verification explicitly retain
  status 86; they are not matching rejections.
- `bin/cppgm.rs`, `driver/ast.rs`, `lower/mod.rs` retain typed definitions for
  optimized source views independently of object-mode lowering. Last-level
  selection and `__OPTIMIZE__` precede preprocessing; startup, entry aliases
  and publication order finish before optimization. Existing O0 streaming
  remains intact. Each parsed frontend unit dies before the completed LowIR
  program crosses the optimizer boundary; no text is reparsed between phases.
- `opt/{inline_policy,mod}.rs`, `driver/{ast,toolchain}.rs` share validated
  inline-limit values across standalone, source-view, source-object and
  LowIR-input object paths. Object preparation permits thunk-target inlining
  for course objects, as C++ does; host objects and text views keep it disabled.
  Option shape/value failure precedence remains separate and ordered.
- `opt/sparse_constants.rs` now derives phi participation from current CFG
  placement, including generated/imported continuation blocks. The parser's
  placement bit is not an optimizer membership fact. This preserves both
  moved caller-phi values instead of incorrectly returning the other edge's
  constant. The regression runs the complete pipeline before compaction.

Architecture review: one owning typed LowIR program; checked IDs and errors;
function-owned analysis tables and versioned scheduling; no frontend retention,
new dependency, unsafe code, environment reads in phases or compiler delegation.
The existing optimizer schedule and native allocator/encoding policy are retained.
