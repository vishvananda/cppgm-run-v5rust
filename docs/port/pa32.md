## Ownership and mechanism

Consulted the handout, contract, spec, conversion plan and frozen
`opt/loop_passes.cpp` (fill recognition/emission, builtin demand, loop scheduling
and bypass), `opt/loops.cpp`, `lowir/{local_names,text_writer}.cpp`, and the
native memset/object/runtime consumers. Detailed ownership stays in
[source-map.tsv](source-map.tsv).

- `opt/loop_fills.rs` translates repeated-byte pointer fills: same-byte integer
  constants, invariant runtime bytes, or one invariant-address byte load.
  Copy-address limits, stride/type tests, store dominance, volatility and
  nonmatching exclusions follow C++. Byte counts reuse the bound's byte index
  or ordered pointer copies/subtraction. Runtime bytes widen to i32; the call
  inherits the store's debug location. The frozen low-word test also applies
  to i128 constants, with explicitly bounded shifts reproducing x86-64 wrapping.
- `opt/loop_removal.rs` completes the O1 decision, existing exit/phi repair and
  scalar consumers. Reference-loaded words, nonuniform/runtime words, live
  secondary phis and nonmatching counted stores remain when C++ declines them.
  Effect-free bypasses and eight-round/sixteen-candidate budgets are unchanged.
- `opt/pass_context.rs` permits typed declaration insertion while exclusively
  owning one detached function body. Memset is declared once on demand with
  exact signature/binding/unwind/object metadata; existing functions are reused,
  and conflicting globals prevent rewriting. `lowir/model.rs` supplies indexed
  name lookup and source-provenance references. `lowir/writer.rs` translates
  anonymous boundary names and underscore collision avoidance, retaining
  borrowed explicit names; a typed unit regression covers collisions.

Architecture review: one typed LowIR program, function-owned rewrite scratch,
checked IDs and existing CFG/version invalidation/compaction. No frontend
retention, text reparsing, dependency, unsafe code, phase environment read,
delegation, optimizer-policy change or native allocator/encoder change.
