## Coherent behavior groups

Implemented and validated within this group:

- Exact standalone help and option handling: O0–O3 duplicate detection,
  `--target linux`, `--stats`, machine dump / legacy native-plan alias,
  output/source requirements, missing/duplicate values and unknown byte options.
  Empty output values retain the oracle's presence rules. Batch query precedence
  retains the unlinked batch protocol's `EXIT_NOT_IMPLEMENTED` responses.
- Read all source files in argument order into one unit, intern retained names,
  finish symbols, assign legacy roles and validate once before output creation.
  The backend borrows typed LowIR; it never serializes or reparses it.
- Entry rejection precedes MIR opening for executable requests. Startup discovery
  walks symbol order, consumes typed roles/signatures and the ABI object name,
  suppresses external `atexit` support if any definition provides that object,
  and preserves entry argument-register and shutdown ordering in its MIR view.
- Data/declaration-only MIR dumps succeed, including no startup section when
  there is no entry. Global definition order, storage metadata, scalar/structured
  items, pointer addends and full 128-bit integer spellings are exact. Integer
  low-word reinterpretation is explicit; the frozen double-minus `i64::MIN` addend display uses explicit signed-word
  wrapping, without host signed overflow.
- Native float spelling reads retained f32/f64/x87 bits and tries bounded general
  decimal precisions 1–9/17/21 until target-width roundtrip. It preserves signed
  zero, finite subnormals, infinity and native NaN spelling. This separate view
  leaves PA8's existing literal serialization unchanged.
- Supported zero-function `--stats` reports zero deterministic selector/encoder
  work and actual elapsed time/RSS. RSS reads remain in `dev/bin/`.

No function selection, register placement/allocation, executable bytes, optimizer
or runtime implementation is claimed. Valid function definitions still return
**86**, after any startup/global view, rather than becoming a generic rejection.
Global payload layout, data/address fixups and executable runtime are still due.

Production ownership review: the shared reader owns one `Program`; names,
symbols, signatures and operands retain their compact IDs and private stores;
each body remains function-owned. Native output is a bounded buffered view over
these facts, with one reusable floating scanner. Startup is the required global
role inventory, not speculative body work. No new dependency, unsafe/FFI code,
compiler subprocess, fixture recognition, environment read in `dev/src/`, lint
suppression or textual phase transport was added. No existing optimizer or
register-allocation behavior was changed. Source responsibilities are recorded
in `docs/port/source-map.tsv` without marking the native owners complete.
